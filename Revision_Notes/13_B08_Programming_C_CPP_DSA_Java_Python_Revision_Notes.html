📖 Chapter 1: C/C++ Fundamentals — C/C++ Storage Classes, Pointers, Dynamic Memory, Struct vs Union & Preprocessor Macros

17 Questions in Booklet
📌 1.1 C/C++ Storage Classes, Pointers, Dynamic Memory, Struct vs Union & Preprocessor Macros
Key Formulas & Rules
  • 🔹 Array-Pointer Identity: arr[i] == *(arr + i) == *(i + arr) == i[arr]
  • 🔹 2D Row-Major Address(A[i][j]) = Base + [(i × Cols) + j] × sizeof(elem)
  • 🔹 Column-Major = Base + [(j × Rows) + i] × W
Simple Exam Points
  • C Storage Classes Table: (1) `auto` (Memory: Stack, Default value: Garbage, Scope: Local block, Lifetime: Function call), (2) `register` (Memory: CPU Register, Default: Garbage, Scope: Local, Note: Cannot apply address-of `&` operator!), (3) `static` (Memory: Data/BSS Segment, Default: Zero `0`, Scope: Local to block/file, Lifetime: Entire program execution — retains value across function calls!), (4) `extern` (Memory: Data Segment, Default: Zero `0`, Scope: Global across multiple files).
  • `struct` allocates sum of all member sizes (plus alignment padding), whereas `union` allocates size equal to its LARGEST member (all members share offset 0).
  • Dangling Pointer points to freed/deallocated memory
  • Memory Leak occurs when heap memory (`malloc`/`new`) loses its pointer without `free()`/`delete`.
✅ Direct Exam Example: Worked Row-Major Address Math: Given 2D array `int A[10][20]` stored in Row-Major order with Base Address = 1000 and `sizeof(int) = 4` bytes. Address of `A[3][5]` = 1000 + (3 × 20 + 5) × 4 = 1000 + 65 × 4 = 1260.
💡 Exam Shortcut / Trap: Hinglish Tip: `static` variable sirf EK baar initialize hota hai (default 0) aur function khatam hone par bhi apni purani value yaad rakhta hai! Aur C me `sizeof('A')` = `sizeof(int)` = 4 bytes hota hai, jabki C++ me `sizeof('A')` = 1 byte hota hai!

📖 Chapter 2: Stacks & Queues — Stacks (LIFO), Infix-to-Postfix/Prefix Conversion, Recursion & Circular Queues (FIFO)

11 Questions in Booklet
📌 2.1 Stacks (LIFO), Infix-to-Postfix/Prefix Conversion, Recursion & Circular Queues (FIFO)
Key Formulas & Rules
  • 🔹 Circular Queue (Array size N): Enqueue -> rear = (rear + 1) % N
  • 🔹 Dequeue -> front = (front + 1) % N
  • 🔹 Full -> (rear + 1) % N == front
  • 🔹 Count = (rear − front + N) % N + 1
Simple Exam Points
  • Stack (LIFO) Operations (`push`, `pop`, `peek` all O(1)) power Function Call Activation Records, Undo/Redo, Backtracking, Balanced Parentheses Checking, and Expression Evaluation.
  • Operator Precedence & Associativity in Infix-to-Postfix: Exponentiation (`^` or `**`) has highest precedence and is RIGHT-associative (`A ^ B ^ C` -> `A B C ^ ^`!)
  • Multiplication/Division (`*`, `/`) are higher than Addition/Subtraction (`+`, `-`) and are LEFT-associative (`A - B - C` -> `A B - C -`).
  • To implement a Queue using Stacks requires minimum 2 Stacks
  • to implement a Stack using Queues requires 2 Queues.
  • Catalan Number `C_n = (1/(n+1)) × (2n choose n)` gives the number of valid stack-sortable permutations of `1..n`!
✅ Direct Exam Example: Worked Postfix Evaluation: Evaluate Postfix expression `6 5 2 3 + 8 * + 3 + *`. Step 1: `2 3 +` = 5. Step 2: `5 8 *` = 40. Step 3: `5 40 +` = 45. Step 4: `45 3 +` = 48. Step 5: `6 48 *` = 288.
💡 Exam Shortcut / Trap: Exam Trap: Exponentiation operator `^` RIGHT-to-LEFT associative hota hai (`2 ^ 3 ^ 2 = 2 ^ 9 = 512`), isliye `A ^ B ^ C` ka Postfix `A B C ^ ^` banta hai (na ki `A B ^ C ^`)!

(B) 1200
(C) 1260 ✅
(D) 1300
Answer (C): 1260 (Base + W × [i × C + j] = 1000 + 4 × [3 × 20 + 5] = 1000 + 4 × 65 = 1260) — In 0-indexed Row-Major order (`C = 20` columns): `Address(A[i][j]) = Base + W × (i × C + j) = 1000 + 4 × (3 × 20 + 5) = 1260`.
Q2.3: Which data structure follows the 'LIFO' (Last-In, First-Out) principle, and what are its two primary applications?
(A) Queue (FIFO)
(B) Binary Search Tree
(C) Hash Table
(D) Stack (LIFO) ✅

Stack (LIFO); used in Function Call Recursion (Activation Records), Infix-to-Postfix conversion, Balanced Parentheses checking, and Undo operations — Stack operates on LIFO (`push` and `pop` at Top in `O(1)` time); Queue operates on FIFO (`enqueue` at Rear, `dequeue` at Front).
Q2.4: Convert the Infix arithmetic expression `A + B * C` into its equivalent Postfix (Reverse Polish) and Prefix (Polish) notations:
(A) Postfix = `A B C * +`; Prefix = `+ A * B C` ✅
(B) Postfix = `A B + C *`; Prefix = `* + A B C`
(C) Postfix = `+ * A B C`
(D) Postfix = `A + B C *`
Answer (A): Since `*` has higher precedence than `+`, `B * C` is evaluated first: Postfix = `A (B C *) +` = `A B C * +`; Prefix = `+ A (* B C)` = `+ A * B C`.
Q2.5: Evaluate the Postfix expression: `6 3 2 + * 4 −`
(A) 16
(B) 26 ✅
(C) 20
(D) 14
Answer (B): Push 6, 3, 2 -> `+` pops 3,2 and pushes `3+2 = 5` -> `*` pops 6,5 and pushes `6×5 = 30` -> push 4 -> `−` pops 30,4 and computes `30 − 4 = 26`.

📖 Chapter 3: Linked Lists — Singly, Doubly & Circular Linked Lists, Pointer Manipulation & Floyd's Cycle Detection

3 Questions in Booklet
📌 3.1 Singly, Doubly & Circular Linked Lists, Pointer Manipulation & Floyd's Cycle Detection
Key Formulas & Rules
  • 🔹 Singly LL Complexities: Insert/Delete at Head = O(1)
  • 🔹 Search = O(n)
  • 🔹 Delete Given Node with Tail/Last -> O(n)
  • 🔹 Reverse Singly LL In-Place = O(n) time, O(1) space (3 pointers: prev, curr, next)
Simple Exam Points
  • In a Singly Linked List, inserting at the head (`newNode->next = head
  • head = newNode;`) and deleting the head take O(1) time.
  • If a Circular Linked List maintains a pointer to the LAST (Tail) node instead of Head (`tail->next` is Head!), BOTH insertion at the front AND insertion at the rear take O(1) constant time!
  • In a Doubly Linked List, inserting a node X after node P executes: `X->next = P->next
  • X->prev = P
  • if(P->next) P->next->prev = X
  • P->next = X;`.
  • Floyd's Cycle-Finding Algorithm (Tortoise and Hare) uses `slow = slow->next` and `fast = fast->next->next` to detect a loop in O(n) time and O(1) auxiliary space.
✅ Direct Exam Example: Xor Linked List (Memory-Efficient Doubly Linked List): Stores `npx = prev ⊕ next` (bitwise XOR of previous and next addresses) in a single pointer field per node, allowing bidirectional traversal using only 1 pointer per node!
💡 Exam Shortcut / Trap: Hinglish Tip: Circular Singly Linked List me agar pointer 'Head' ke bajay 'Last/Tail node' par rakha jaye, to Front aur Rear DONO jagah insertion O(1) time me ho jata hai (kyunki `last->next` hi Head hota hai)!

(A) Singly Linked List node has 1 pointer (`next`) ✅
(B) Singly Linked List allows O(1) backward traversal
(C) Doubly Linked List uses less memory per node than Singly Linked List
(D) Linked lists store nodes in contiguous memory
Answer (A): Singly Linked List node has 1 pointer (`next`); Doubly Linked List node has 2 pointers, allowing bidirectional traversal and `O(1)` deletion of a node given only a pointer to that node itself. Singly Linked List node has 1 pointer (`next`); Doubly Linked List node has 2 pointers (`prev` and `next`), allowing bidirectional traversal and `O(1)` deletion of a node given only a pointer to that node itself — In a Singly Linked List, deleting a node `p` requires knowing its predecessor (`O(n)` search unless head), whereas a Doubly Linked List accesses `p->prev` directly in `O(1)` time.
Q3.2: What is the time complexity of finding the middle element or detecting a cycle in a Singly Linked List of `n` nodes using Floyd's Cycle-Finding (Tortoise and Hare / Slow and Fast Pointer) Algorithm?
(A) O(n²) time and O(n) space
(B) O(n) time and O(1) auxiliary space ✅
(C) O(log n) time
(D) It requires modifying node values
Answer (B): O(n) time and O(1) auxiliary space (Slow pointer moves 1 step `slow = slow->next`, Fast pointer moves 2 steps `fast = fast->next->next`) — Floyd's two-pointer technique detects a cycle (when `slow == fast`) or finds the middle node (when `fast` reaches `NULL`) in a single `O(n)` pass with `O(1)` extra space.
Q3.3: In a Circular Linked List, what does the `next` pointer of the LAST node point to?
(A) It points to `NULL`
(B) It points to itself always
(C) It points back to the FIRST (`head`) node ✅
(D) It points to the middle node
Answer (C): It points back to the FIRST (`head`) node (never `NULL`) — In a Circular Linked List, the last node's `next` links back to `head`, forming a closed ring.

📖 Chapter 4: Trees & BST — Binary Trees, Traversals (Inorder, Preorder, Postorder), BSTs, AVL Rotations & Binary Heaps

10 Questions in Booklet
📌 4.1 Binary Trees, Traversals (Inorder, Preorder, Postorder), BSTs, AVL Rotations & Binary Heaps
Key Formulas & Rules
  • 🔹 Binary Tree Degree-0/2 Theorem: Leaf Nodes L = n_2 + 1
  • 🔹 Max Nodes at Level l (root=0) = 2^l
  • 🔹 Max Nodes of Height h = 2^(h+1) − 1
  • 🔹 Strictly Binary Tree (n_1=0) Total Nodes = 2L − 1
Simple Exam Points
  • Tree Traversals: Preorder (`Root-Left-Right`), Inorder (`Left-Root-Right`), Postorder (`Left-Right-Root`).
  • Crucial Theorem: Inorder traversal of a Binary Search Tree (BST) ALWAYS produces keys in strictly sorted ascending order!
  • To uniquely reconstruct a general Binary Tree, you MUST have Inorder + (Preorder OR Postorder OR Level-order)
  • Preorder + Postorder alone CANNOT uniquely reconstruct a general binary tree (unless it is a Full/Strict Binary Tree).
  • AVL Tree (Height-Balanced BST where Balance Factor `BF = |h_L − h_R| <= 1` for every node): LL and RR imbalances require a Single Rotation (1 rotation)
  • LR and RL imbalances require a Double Rotation (2 rotations).
  • A Binary Heap is a Complete Binary Tree stored in an array (for 0-indexed node `i`, Left Child = `2i+1`, Right Child = `2i+2`, Parent = `⌊(i−1)/2⌋`).
✅ Direct Exam Example: Worked Tree Reconstruction: Given Inorder `D B E A F C` and Preorder `A B D E C F`. First node of Preorder is Root (`A`). In Inorder, `D B E` is Left subtree and `F C` is Right subtree. Recursively, Postorder (`Left-Right-Root`) is `D E B F C A`.
💡 Exam Shortcut / Trap: Exam Trap: Kisi bhi Binary Tree me Leaf nodes (degree 0) ki sankhya hamesha Degree-2 wale internal nodes se EK ZYADA hoti hai (`L = n_2 + 1`)! Aur Binary Tree ko uniquely construct karne ke liye 'Inorder' traversal hona 100% zaroori hai!

📝 Chapter 4 — Practice Questions & Simple Explanations

Q4.1: What is the maximum number of nodes at level `k` (where root is at level `0`) and the maximum total nodes in a Binary Tree of height `h` (root at height 0)?
(A) Max at level k = 2k; Max total = 2^h
(B) Max at level k = k²; Max total = h + 1
(C) Max total = 2^h − 1
(D) Max nodes at level k = 2^k; Max total nodes of height h = 2^(h+1) − 1 ✅
Answer (D): At level 0 (root): `2⁰ = 1` node; level 1: `2¹ = 2` nodes; level `k`: `2^k` nodes. Sum from `0` to `h` = `2^(h+1) − 1`.
Q4.2: In any strict (full) Binary Tree where every internal node has exactly 2 children, if there are `I` internal nodes, how many Leaf nodes `L` are there?
(A) L = I + 1 ✅
(B) L = I
(C) L = 2I
(D) L = I − 1
Answer (A): L = I + 1 (Number of Leaf nodes is always 1 more than the number of degree-2 internal nodes) — In any binary tree, the number of leaf nodes `n₀` and degree-2 nodes `n₂` always satisfy `n₀ = n₂ + 1`.
Q4.3: Which pair of tree traversals is required and sufficient to uniquely reconstruct a general Binary Tree?
(A) Preorder + Postorder Traversal (cannot distinguish left vs right child when a node has 1 child)
(B) Inorder Traversal + Preorder Traversal (OR Inorder + Postorder Traversal) ✅
(C) Only Preorder Traversal
(D) Only Level-Order Traversal
Answer (B): Preorder gives the Root first (`[Root] [Left] [Right]`), and Inorder splits `[Left] [Root] [Right]` uniquely.
Q4.4: In an AVL (Height-Balanced Binary Search) Tree, what are the only permissible values of the Balance Factor (`BF = Height(Left) − Height(Right)`) at every node?
(A) {0} only
(B) {−2, −1, 0, +1, +2}
(C) {−1, 0, +1} ✅
(D) Any integer
Answer (C): If an insertion or deletion causes `|BF| = 2`, the AVL tree restores balance in `O(1)` rotations (`LL, RR` single rotations or `LR, RL` double rotations).
Q4.5: In a Hash Table of size `m` holding `n` keys, what is the Load Factor `α`, and what are the two main families of Collision Resolution techniques?
(A) Load Factor α = m × n
(B) Collisions cannot occur in hashing
(C) Linear Probing eliminates Primary Clustering
(D) Load Factor α = n / m; 1. Separate Chaining and 2. Open Addressing ✅
Answer (D): Load Factor α = n / m; 1. Separate Chaining (open hashing using linked lists) and 2. Open Addressing (Linear Probing, Quadratic Probing, Double Hashing) — Linear Probing (`(h(k) + i) mod m`) suffers from **Primary Clustering**; Quadratic Probing (`(h(k) + i²) mod m`) suffers from **Secondary Clustering**; Double Hashing (`(h₁(k) + i · h₂(k)) mod m`) eliminates both.

📖 Chapter 5: OOP Principles — OOP Four Pillars, Access Specifiers, Constructors/Destructors, Virtual Functions & vtable

6 Questions in Booklet
📌 5.1 OOP Four Pillars, Access Specifiers, Constructors/Destructors, Virtual Functions & vtable
Key Formulas & Rules
  • 🔹 Compile-Time (Static/Early) Binding = Function & Operator Overloading
  • 🔹 Run-Time (Dynamic/Late) Binding = Function Overriding via `virtual` keyword + vptr/vtable
Simple Exam Points
  • Encapsulation binds data and methods while Data Hiding restricts direct access via `private`/`protected`/`public` specifiers.
  • Inheritance Modes in C++: Public inheritance preserves `public -> public` and `protected -> protected`
  • Protected inheritance turns both into `protected`
  • Private inheritance turns both into `private` (Note: `private` base members are NEVER directly accessible in derived classes!).
  • Constructor vs Destructor Order: Constructors execute from Base -> Derived (Top-Down), whereas Destructors execute in exact reverse order from Derived -> Base (Bottom-Up)!
  • Always declare Base class destructors `virtual` to prevent memory leaks when deleting a derived object through a base pointer.
  • C++ Operators that CANNOT be overloaded: `::` (Scope resolution), `.` (Member access), `.*` (Pointer-to-member), `?:` (Ternary conditional), and `sizeof`!
✅ Direct Exam Example: Diamond Problem in Multiple Inheritance: When class D inherits from B and C which both inherit from A, D gets two copies of A's members (ambiguity error), resolved in C++ using `virtual public A` (Virtual Base Class).
💡 Exam Shortcut / Trap: Hinglish Tip: C++ me 5 operators kabhi overload NAHI ho sakte: `.`, `.*`, `::`, `?:`, aur `sizeof`! Aur Constructor hamesha Base-to-Derived chalta hai, jabki Destructor ulta Derived-to-Base chalta hai!

Answer (B): 1. Encapsulation (Data Hiding), 2. Abstraction, 3. Inheritance (IS-A relationship), and 4. Polymorphism — Encapsulation binds data + methods and hides private state; Inheritance enables code reuse; Polymorphism = 'One interface, multiple implementations'.

Compile-Time Polymorphism = Function Overloading & Operator Overloading (early binding); Run-Time Polymorphism = Method Overriding via `virtual` functions (late binding) — Note: In C++, **Constructors can NEVER be `virtual`**, whereas base class **Destructors SHOULD be `virtual`** so derived objects are cleaned up properly via base pointers.
Q5.3: In C++ and Java Inheritance, which members of a Base class are accessible inside a Derived subclass, and which access specifier keeps members private to outside classes while allowing subclass access?

(B) A member function inherited by all subclasses

Answer (A): A non-member function (or another class) granted special permission by a class to access its `private` and `protected` members directly — Note: In C++, **Friendship is NOT mutual, NOT inherited, and NOT transitive** (if A is a friend of B, and B is a friend of C, A is NOT automatically a friend of C).
Q5.5: In C++, what is a 'Pure Virtual Function' (`virtual void draw() = 0;`), and what is a class containing at least one Pure Virtual Function called?

(B) A virtual function equated to `= 0` with no required base implementation ✅

📖 Chapter 6: Java Architecture — Java Architecture (JDK/JRE/JVM), Bytecode, String Pool, Exception Handling & Multithreading

5 Questions in Booklet
📌 6.1 Java Architecture (JDK/JRE/JVM), Bytecode, String Pool, Exception Handling & Multithreading
Key Formulas & Rules
  • 🔹 Java `==` compares Object Reference (Memory Address) vs `.equals()` compares Content
  • 🔹 `final` (Constant/No-Override/No-Inherit) vs `finally` (Always executes) vs `finalize()` (GC hook)
Simple Exam Points
  • Java compiles `.java` source into platform-independent `.class` Bytecode executed by the JVM (Interpreter + JIT Compiler).
  • In Java, `String` objects are strictly IMMUTABLE (stored in the String Constant Pool inside the Heap
  • `StringBuffer` is mutable & thread-safe synchronized
  • `StringBuilder` is mutable & faster non-synchronized).
  • Java does NOT support multiple inheritance of classes (to avoid the Diamond Problem), achieving it instead through `interface`.
  • Exception Hierarchy (`Throwable` -> `Error` vs `Exception` -> Checked Exceptions vs Unchecked `RuntimeException`).
  • A `finally` block ALWAYS executes whether an exception is thrown or caught, EXCEPT when `System.exit(0)` or a fatal JVM crash occurs!

  • Default Mutable Argument Trap: `def append_to(x, lst=[]): lst.append(x)
  • return lst` evaluates the default list `[]` ONLY ONCE at function definition time (`def`), sharing the same list across subsequent calls!
  • Floor division `//` rounds toward negative infinity (`-7 // 2 == -4`, whereas `7 // 2 == 3`, and `-7 % 2 == 1`).
