📌 1.1 Display Technologies (Raster vs Random Scan CRT, LCD, LED), Refresh Rate & Frame Buffer Math
Key Formulas & Rules
  • 🔹 Frame Buffer Memory (Bytes) = (Width × Height × Bits_per_Pixel) / 8
  • 🔹 Aspect Ratio = Horizontal Pixels : Vertical Pixels (e.g., 16:9, 4:3)
  • 🔹 True Color = 24-bit RGB (16.77 Million colors); RGBA = 32-bit
Simple Exam Points
  • CRT Display Architectures: (1) **Raster Scan Display**: Electron beam sweeps across the entire screen row-by-row from top to bottom (Horizontal Retrace at end of each scanline
  • Vertical Retrace from bottom-right back to top-left at 60–120 Hz), reading pixel intensities from a **Frame Buffer (Refresh Buffer)**.
  • Produces realistic shaded scenes and filled polygons, but suffers from staircase aliasing (jaggies)
  • (2) **Random Scan (Vector / Calligraphic / Stroke) Display**: Electron beam is directed ONLY to the parts of the screen where a picture is to be drawn, drawing smooth constituent lines one by one from a Display File (ideal for wireframe CAD engineering drawings, cannot render realistic shaded photos).
  • Color CRTs use **Beam Penetration** (2 phosphor layers: Red outer, Green inner
  • slow/medium/fast beam yields 4 colors: Red, Orange, Yellow, Green — used in Random Scan) or **Shadow Mask** (3 electron guns R, G, B + perforated metal shadow mask with triad phosphor dots — used in Raster Scan TV/monitors).
✅ Direct Exam Example: Worked Frame Buffer Numerical: How much video RAM (Frame Buffer) is required for a Full HD `1920 × 1080` display with 24-bit True Color (3 Bytes per pixel)? Size = `1920 × 1080 × 3` Bytes = `6,220,800` Bytes ≈ `5.93 MB` (or for `1024 × 1024` at 24-bit = `3 MB`).
💡 Exam Shortcut / Trap: Hinglish Tip: **Beam Penetration CRT** me sirf 2 phosphor layers (Red + Green) hoti hain aur **4 colors** (Red, Orange, Yellow, Green) milte hain; jabki **Shadow Mask CRT** me 3 guns (R, G, B) hoti hain aur millions of True Colors milte hain!

Q1.1: A raster-scan graphics monitor has a display resolution of 1920 × 1080 pixels and uses 24-bit True Color (8 bits each for R, G, and B). What is the exact size of the frame buffer required to store one single frame in Megabytes (using 1 MB = 10⁶ bytes or exact bytes)?
(A) 6,220,800 Bytes (≈ 5.93 MiB / 6.22 MB) ✅
(B) 2,073,600 Bytes (≈ 2 MB)
(C) 4,147,200 Bytes (≈ 4 MB)
(D) 49,766,400 Bytes (≈ 49.7 MB)
Answer (A): Total pixels = 1920 × 1080 = 2,073,600. At 24 bits = 3 Bytes per pixel, Frame Buffer = 2,073,600 × 3 = 6,220,800 Bytes (÷ 1,048,576 = 5.9326 MiB).
Q1.2: Which of the following statements accurately distinguishes a Random-Scan (Vector) display from a Raster-Scan display?
(A) Random-scan is ideal for shaded photorealistic images, whereas Raster-scan can only draw wireframes
(B) Random-scan draws lines directly between endpoint coordinates with smooth diagonal lines, whereas Raster-scan sweeps all scan lines sequentially and exhibits staircasing (aliasing) ✅
(C) Random-scan stores pixel intensities in a 2D bitmap frame buffer, whereas Raster-scan stores a display list of line commands
(D) Raster-scan has higher resolution for line drawings than Random-scan and never requires anti-aliasing
Answer (B): Vector (Random-scan) monitors direct the electron beam only along the component lines of an object, producing smooth curves/diagonals without aliasing, but cannot render realistic shaded scenes.
Q1.3: In a Color CRT monitor, which method coats the screen with small triangular clusters ('triads') of Red, Green, and Blue phosphor dots and uses a perforated metal grid to align the three electron guns?
(A) Beam-Penetration Method
(B) Direct-View Storage Tube (DVST)
(C) Shadow-Mask Method (Delta-Delta Method) ✅
(D) Plasma Panel Discharge
Answer (C): Shadow-mask CRTs use three electron guns (R, G, B) and a perforated shadow mask to produce millions of full-color shades; Beam-penetration uses 2 phosphor layers (red/green) and only produces 4 colors (red, orange, yellow, green) for random-scan.
Q1.4: What is the primary purpose of 'Interlacing' in raster-scan television and video displays?
(A) To double the spatial pixel resolution of the frame buffer
(B) To convert RGB color coordinates into CMYK printer coordinates
(C) To compress video frames using Discrete Cosine Transform
(D) To reduce visible screen flicker at lower frame rates by scanning odd-numbered lines in the first half-cycle and even-numbered lines in the second half-cycle ✅
Answer (D): Interlacing splits each frame into two fields (odd scan lines then even scan lines), doubling the effective field refresh rate (e.g., 30 Hz frame rate appears as 60 Hz field rate) to eliminate flicker.
Q1.5: A display monitor has a screen resolution of `1024 × 768` pixels. If the horizontal width of the active display area is `16 inches` and the vertical height is `12 inches`, what is the Aspect Ratio of the display and its Dots Per Inch (DPI) resolution?
(A) Aspect Ratio = 4:3; Resolution = 64 DPI ✅
(B) Aspect Ratio = 16:9; Resolution = 96 DPI
(C) Aspect Ratio = 4:3; Resolution = 128 DPI
(D) Aspect Ratio = 5:4; Resolution = 72 DPI
Answer (A): Aspect Ratio = 4:3; Resolution = 64 DPI (both horizontally 1024/16 = 64 and vertically 768/12 = 64) — Aspect Ratio = `1024 : 768 = 4 : 3` (and `16 : 12 = 4 : 3`). Horizontal DPI = `1024 / 16 = 64 DPI`; Vertical DPI = `768 / 12 = 64 DPI` (square pixels).

📖 Chapter 2: Scan Conversion — Scan Conversion Algorithms — DDA vs Bresenham's Line, Midpoint Circle (8-Way Symmetry) & Area Fill

📌 2.1 Scan Conversion Algorithms — DDA vs Bresenham's Line, Midpoint Circle (8-Way Symmetry) & Area Fill
Key Formulas & Rules
  • 🔹 Bresenham Line (0 < m < 1): Initial Decision Parameter p_0 = 2Δy − Δx (If p_k < 0: next y_k, p_(k+1) = p_k + 2Δy; If p_k >= 0: next y_k + 1, p_(k+1) = p_k + 2Δy − 2Δx)
  • 🔹 Midpoint Circle p_0 = 1 − r (or 5/4 − r)
Simple Exam Points
  • Line Drawing Algorithms: (1) **DDA (Digital Differential Analyzer)**: Incremental algorithm using `steps = max(|Δx|, |Δy|)` and floating-point additions `x_(k+1) = x_k + x_inc, y_(k+1) = y_k + y_inc` followed by `round()` — suffers from slow floating-point arithmetic and cumulative rounding drift
  • (2) **Bresenham's Line Algorithm**: Uses ONLY fast integer addition, subtraction, and bit-shifting (`×2`), completely eliminating floating-point operations and rounding errors!
  • **Midpoint Circle Algorithm** exploits **8-Way Octant Symmetry** `(±x, ±y)` and `(±y, ±x)` so computing just a 45° octant arc from `x = 0` to `x = y` plots the entire circle!
  • Polygon Filling: **Boundary Fill** fills outward until hitting a specified `boundary_color`
  • **Flood Fill** replaces a connected interior `old_color` with `new_color` (using 4-connected or 8-connected neighbors).
✅ Direct Exam Example: Worked DDA & Bresenham Step Count: To rasterize a line from `(2, 3)` to `(12, 8)`, `Δx = 10` and `Δy = 5`. Number of steps = `max(10, 5) = 10`. Initial Bresenham decision parameter `p_0 = 2(5) − 10 = 0`.
💡 Exam Shortcut / Trap: Exam Trap: **DDA** floating-point arithmetic aur `round()` function use karta hai (slow + cumulative drift), jabki **Bresenham's Line Algorithm** 100% pure **Integer Addition/Subtraction** par chalta hai (`p_0 = 2Δy − Δx`)!

📝 Chapter 2 — Practice Questions & Simple Explanations

Q2.1: Why is Bresenham's Line Drawing Algorithm significantly faster in hardware and firmware than the Digital Differential Analyzer (DDA) algorithm?
(A) Bresenham uses only integer addition, subtraction, and bit-shifting, completely avoiding floating-point arithmetic and rounding ✅
(B) Bresenham uses trigonometric sine and cosine lookup tables
(C) Bresenham calculates two pixels simultaneously using matrix inversion
(D) DDA can only draw horizontal and vertical lines
Answer (A): Bresenham uses only integer addition, subtraction, and bit-shifting (multiplication by 2), completely avoiding floating-point arithmetic and rounding — DDA requires floating-point addition (`x = x + 1/m`) and `round()` at every step, whereas Bresenham uses an integer decision parameter `p_k` updated via integer additions and `2Δy` shifts.
Q2.2: In Bresenham's Line Algorithm for a line with positive slope `0 < m < 1` (`Δx > 0, Δy > 0`), what is the initial decision parameter `p_0`, and how is `p_{k+1}` updated when `p_k < 0`?
(A) p_0 = Δy − 2Δx; when p_k < 0, p_{k+1} = p_k + 2Δx
(B) p_0 = 2Δy − Δx; when p_k < 0, next pixel is and p_{k+1} = p_k + 2Δy ✅
(C) p_0 = 2Δy − 2Δx; when p_k < 0, p_{k+1} = p_k + 2Δy − 2Δx
(D) p_0 = 1 − r; when p_k < 0, p_{k+1} = p_k + 2x + 3
Answer (B): p_0 = 2Δy − Δx; when p_k < 0, next pixel is (x_k + 1, y_k) and p_{k+1} = p_k + 2Δy — For `0 < m < 1`, `p_0 = 2Δy - Δx`. If `p_k < 0`, `y` stays unchanged and `p_{k+1} = p_k + 2Δy`; if `p_k ≥ 0`, `y` increments by 1 and `p_{k+1} = p_k + 2Δy - 2Δx`.
Q2.3: How many octants of symmetry does the Midpoint Circle Algorithm exploit so that computing pixel coordinates for just a single 45° arc (from x = 0 to x = y) generates the entire circle?
(A) 4-Way Symmetry (only across X and Y axes)
(B) 2-Way Symmetry
(C) 8-Way Symmetry (±x, ±y) and (±y, ±x) ✅
(D) 16-Way Symmetry
Answer (C): A circle centered at the origin exhibits 8-fold octant symmetry: if `(x, y)` is on the circle, then `(±x, ±y)` and `(±y, ±x)` give 8 points simultaneously (whereas an ellipse has only 4-way symmetry).
Q2.4: In the Midpoint Circle Drawing Algorithm starting at `(0, r)` for a circle of integer radius `r`, what is the exact integer value of the initial decision parameter `p_0`?
(A) p_0 = 3 − 2r
(B) p_0 = 2r − 1
(C) p_0 = r − 1
(D) p_0 = 1 − r ✅
Answer (D): p_0 = 1 − r (rounded from 5/4 − r) — In the Midpoint Circle Algorithm, `p_0 = 5/4 - r`, which for integer radii is initialized as `p_0 = 1 - r` (in Bresenham's Circle Algorithm, `d_0 = 3 - 2r`).
Q2.5: Using the DDA (Digital Differential Analyzer) Line Drawing Algorithm to rasterize a line from `(2, 3)` to `(12, 8)`, what are `Δx, Δy`, the number of `steps`, and the increments `(x_inc, y_inc)` per step?
(A) Δx = 10, Δy = 5, steps = max(|Δx|, |Δy|) = 10; x_inc = 1.0, y_inc = 0.5 ✅
(B) Δx = 5, Δy = 10, steps = 5; x_inc = 2.0, y_inc = 1.0
(C) steps = 15; x_inc = 0.5, y_inc = 1.0
(D) steps = 10; x_inc = 0.5, y_inc = 2.0
Answer (A): In DDA: `Δx = 12 - 2 = 10`, `Δy = 8 - 3 = 5`. Since `|Δx| > |Δy|` (gentle slope `m = 0.5`), `steps = 10`, `x_inc = Δx / steps = 1.0`, and `y_inc = Δy / steps = 0.5`.

📌 3.1 2D & 3D Geometric Transformations, Homogeneous Coordinates & Composite Transformation Matrices
Key Formulas & Rules
  • 🔹 Homogeneous 2D Point = (x, y, 1) [3×3 Matrix]
  • 🔹 3D Point = (x, y, z, 1) [4×4 Matrix]
  • 🔹 Rotation by θ about Pivot (x_p, y_p): M = T(x_p, y_p) · R(θ) · T(−x_p, −y_p)
Simple Exam Points
  • Why Homogeneous Coordinates?
  • In standard 2×2 Cartesian coordinates, Rotation (`x' = x cos θ − y sin θ, y' = x sin θ + y cos θ`) and Scaling (`x' = x·S_x, y' = y·S_y`) are matrix multiplications, but Translation (`x' = x + t_x, y' = y + t_y`) is vector addition!
  • Representing a 2D point `(x, y)` as a 3-element homogeneous vector `(x, y, 1)` turns Translation into a 3×3 matrix multiplication, allowing any sequence of Translations, Rotations, Scalings, and Shears to be concatenated into a single 3×3 Composite Transformation Matrix!
  • Commutativity Rules: T1·T2 = T2·T1 (2 translations commute), R1·R2 = R2·R1 (2 rotations about same axis commute), S1·S2 = S2·S1 (2 scalings commute), and Uniform Scaling + Rotation commute
  • in general, **Matrix Multiplication of Transformations is NOT Commutative (`R · T ≠ T · R`)**!
✅ Direct Exam Example: Worked 2D Transformation Math: Translate point `P(2, 3)` by `(t_x=4, t_y=−1)` -> `P1(6, 2)`. Then rotate `P1(6, 2)` counter-clockwise by `θ = 90°` about origin (`x' = −y, y' = x`) -> Final point `P2(−2, 6)`. Reflection across line `y = x` swaps coordinates `(x, y) -> (y, x)`; reflection across `y = −x` gives `(−y, −x)`.
💡 Exam Shortcut / Trap: Hinglish Tip: Kisi arbitrary pivot point `(x_p, y_p)` ke around rotate ya scale karne ke 3 steps hote hain: (1) Translate pivot to Origin `T(−x_p, −y_p)`, (2) Rotate/Scale about Origin `R(θ)`, (3) Translate back `T(+x_p, +y_p)`!

📝 Chapter 3 — Practice Questions & Simple Explanations

Q3.1: Why are 2D points `(x, y)` represented using 3-element Homogeneous Coordinates `(x, y, 1)` in computer graphics pipelines?
(A) So that translation can be represented as a 3×3 matrix multiplication and combined with rotation and scaling into a single composite 3×3 matrix ✅
(B) To convert 2D wireframes automatically into 3D solid models
(C) To reduce the memory size of vertex arrays by 33%
(D) To eliminate the need for trigonometric functions in rotation
Answer (A): So that translation (which is otherwise vector addition) can be represented as a 3×3 matrix multiplication and combined with rotation and scaling into a single composite 3×3 matrix — In 2×2 matrices, rotation and scaling are multiplications (`P' = M·P`) while translation is addition (`P' = P + T`). Using 3×3 homogeneous coordinates `(x, y, 1)` makes translation a matrix multiplication too.
Q3.2: What is the correct sequence of three basic 2D transformations required to rotate an object by an angle `θ` about an arbitrary pivot point `(x_p, y_p)`?
(A) 1. Translate by (+x_p, +y_p) -> 2. Rotate by θ -> 3. Translate by (−x_p, −y_p)
(B) 1. Translate by (−x_p, −y_p) -> 2. Rotate about origin by θ -> 3. Translate back by (+x_p, +y_p) ✅
(C) 1. Rotate by θ -> 2. Translate by (x_p, y_p) -> 3. Scale by (x_p, y_p)
(D) 1. Scale by (−1, −1) -> 2. Rotate by θ -> 3. Scale by (+1, +1)
Answer (B): To rotate about `(x_p, y_p)`: shift pivot to origin `T(-x_p, -y_p)`, apply origin rotation `R(θ)`, and shift pivot back `T(x_p, y_p)`. For column vectors, composite matrix = `T(x_p, y_p) · R(θ) · T(-x_p, -y_p)`.
Q3.3: If a 2D point `P(4, 3)` undergoes X-direction shearing with shear parameter `sh_x = 2` (relative to the X-axis, so `x' = x + sh_x · y` and `y' = y`), what are the transformed coordinates `P'(x', y')`?
(A) (4, 11)
(B) (8, 6)
(C) (10, 3) ✅
(D) (6, 5)
Answer (C): Under X-shear (`sh_x = 2`): `x' = x + sh_x · y = 4 + 2(3) = 10` and `y' = y = 3`, giving `(10, 3)`.
Q3.4: Reflecting a 2D point `(x, y)` simultaneously across both the X-axis and the Y-axis (`(x, y) -> (−x, −y)`) is geometrically equivalent to:
(A) A pure rotation of 90° counterclockwise about the origin
(B) Reflection across the line y = x
(C) Scaling by (+1, −1)
(D) A pure rotation of 180° about the origin ✅
Answer (D): At `θ = 180°`, `cos 180° = -1` and `sin 180° = 0`, so rotation by 180° maps `(x, y)` to `(-x, -y)`, identical to reflection through the origin.
Q3.5: What is the `3 × 3` Homogeneous Coordinate Matrix for 2D Counterclockwise Rotation by angle `θ` about the origin `(0, 0)` (assuming column-vector convention `[x', y', 1]^T = R(θ) · [x, y, 1]^T`)?
(A) Row 1: [cos θ, −sin θ, 0], Row 2: [sin θ, cos θ, 0], Row 3: [0, 0, 1] ✅
(B) Row 1: [cos θ, sin θ, 0], Row 2: [−sin θ, cos θ, 0], Row 3: [0, 0, 1] (Clockwise rotation)
(C) Row 1: [sin θ, cos θ, 0], Row 2: [cos θ, −sin θ, 0], Row 3: [0, 0, 1]
(D) Row 1: [1, 0, cos θ], Row 2: [0, 1, sin θ], Row 3: [0, 0, 1]
Answer (A): For column vectors: `x' = x cos θ − y sin θ` and `y' = x sin θ + y cos θ`. Furthermore, the rotation matrix `R(θ)` is orthogonal (`R^{-1}(θ) = R(-θ) = R^T(θ)`) with determinant `det(R) = cos²θ + sin²θ = +1`.

📌 4.1 Viewing Pipeline, Window-to-Viewport Mapping & Line/Polygon Clipping (Cohen-Sutherland, Liang-Barsky, Sutherland-Hodgman)
Key Formulas & Rules
  • 🔹 Cohen-Sutherland 4-Bit Region Outcode = [Bit 4: Top (y > y_max) | Bit 3: Bottom (y < y_min) | Bit 2: Right (x > x_max) | Bit 1: Left (x < x_min)] = TBRL
Simple Exam Points
  • Window (world-coordinate area selected for display: *what* to view) vs Viewport (screen-coordinate area where it is mapped: *where* to display).
  • **Cohen-Sutherland Line Clipping** assigns a 4-bit `TBRL` outcode to both endpoints `O1` and `O2`: (1) **Trivial Acceptance**: If `O1 == 0000` AND `O2 == 0000` (`(O1 | O2) == 0`), the line is 100% inside the window
  • (2) **Trivial Rejection**: If `(O1 & O2) != 0000` (bitwise AND is non-zero, meaning both endpoints share at least one outside region bit), the line is 100% outside and discarded immediately
  • (3) Otherwise, clip against window boundaries!
  • **Liang-Barsky Line Clipping** uses parametric line equations (`u ∈ [0,1]`) and is faster than Cohen-Sutherland.
  • **Sutherland-Hodgman Polygon Clipping** clips a polygon sequentially against each of the 4 window edges (works for convex polygons
  • **Weiler-Atherton** handles concave polygons without extraneous connecting lines).
✅ Direct Exam Example: Worked Outcode Check: Clipping window is `(x_min=10, y_min=10)` to `(x_max=50, y_max=40)`. Point `P(5, 45)` has `y=45 > 40` (Top=1), `y not < 10` (Bottom=0), `x not > 50` (Right=0), `x=5 < 10` (Left=1) => Outcode `TBRL = 1001`.
💡 Exam Shortcut / Trap: Exam Trap: Cohen-Sutherland Outcode ka bit order **TBRL (Top-Bottom-Right-Left)** hota hai! Agar `O1 & O2 != 0000` hai to line 100% Trivial Reject hogi; par agar `O1 & O2 == 0000` (aur `O1, O2 ≠ 0`) hai, to line window ko cross KAR BHI sakti hai aur NAHI BHI (intersection check zaroori hai)!

📝 Chapter 4 — Practice Questions & Simple Explanations

Q4.1: In the Cohen-Sutherland Line Clipping Algorithm using a 4-bit region outcode `(Top, Bottom, Right, Left) = (TBRL)`, under what exact bitwise condition is a line segment with endpoint outcodes `C1` and `C2` trivially REJECTED (completely outside)?
(A) When the bitwise OR of the two outcodes is zero: (C1 | C2) == 0000
(B) When (C1 ^ C2) == 1111
(C) When the bitwise AND of the two outcodes is non-zero: (C1 & C2) != 0000 ✅
(D) When C1 == 0000 and C2 != 0000
Answer (C): If `(C1 | C2) == 0000`, the line is trivially accepted (completely inside). If `(C1 & C2) != 0000`, both endpoints share at least one outside half-plane (both above, below, left, or right), so the segment is trivially rejected.
Q4.2: Which line clipping algorithm uses the parametric representation of a line (`x = x1 + u·Δx, y = y1 + u·Δy` for `0 ≤ u ≤ 1`) and four inequality parameters (`p_k, q_k`) to achieve higher efficiency than Cohen-Sutherland?
(A) Sutherland-Hodgman Algorithm
(B) Weiler-Atherton Algorithm
(C) Midpoint Subdivision Algorithm
(D) Liang-Barsky Line Clipping Algorithm ✅
Answer (D): Liang-Barsky (extending Cyrus-Beck to axis-aligned rectangular windows) computes parameter bounds `u1 = max(0, q_k/p_k for p_k < 0)` and `u2 = min(1, q_k/p_k for p_k > 0)`, rejecting if `u1 > u2`.
Q4.3: Which clipping algorithm is specifically designed to clip a 2D polygon against the four edges of a convex clipping window in a pipeline of four boundary clippers?
(A) Sutherland-Hodgman Polygon Clipping Algorithm ✅
(B) Cohen-Sutherland Algorithm
(C) Bresenham's Algorithm
(D) Z-Buffer Algorithm
Answer (A): Sutherland-Hodgman clips a polygon vertex list sequentially against Left, Right, Bottom, and Top window boundaries using 4 cases (In->In, In->Out, Out->Out, Out->In). For concave polygons that may split into pieces, Weiler-Atherton is used.
Q4.4: In the 2D Window-to-Viewport Coordinate Transformation mapping a world-coordinate window `[xw_min, xw_max] × [yw_min, yw_max]` onto a screen viewport `[xv_min, xv_max] × [yv_min, yv_max]`, what are the scaling factors `s_x` and `s_y`?
(A) s_x = (xw_max − xw_min) / (xv_max − xv_min)
(B) s_x = / and s_y = / ✅
(C) s_x = xv_max × xw_max
(D) s_x = xv_min − xw_min
Answer (B): s_x = (xv_max − xv_min) / (xw_max − xw_min) and s_y = (yv_max − yv_min) / (yw_max − yw_min) — A point `(xw, yw)` maps to viewport `(xv, yv)` via relative proportion: `xv = xv_min + (xw - xw_min) · s_x` and `yv = yv_min + (yw - yw_min) · s_y`.
Q4.5: A rectangular clipping window has lower-left corner `(xw_min, yw_min) = (10, 20)` and upper-right corner `(xw_max, yw_max) = (80, 90)`. 📌 5.1 3D Projections (Parallel vs Perspective) & Visible Surface Detection (Back-Face, Z-Buffer, Painter's, BSP)
Key Formulas & Rules
  • 🔹 Perspective Projection: Parallel lines converge at Vanishing Points (1-Point, 2-Point, 3-Point max along principal axes) & Foreshortening occurs
  • 🔹 Parallel Projection (Orthographic/Oblique): Preserves parallel lines & exact dimensions
Simple Exam Points
  • Visible Surface Detection (Hidden Surface Removal) Algorithms are classified into two categories: (1) **Object-Space Methods** (compare geometric objects/faces in 3D world space at continuous precision — e.g., **Back-Face Detection** where a polygon surface with normal vector `N` and viewing vector `V` is a hidden back-face if `V · N > 0`, **BSP Tree**)
  • (2) **Image-Space Methods** (determine visibility point-by-point at each pixel in screen space — e.g., **Z-Buffer / Depth-Buffer Algorithm**, **Scan-Line Algorithm**, **Warnock's Area-Subdivision Algorithm** using Quadtree of 4 cases: Surrounding, Overlapping, Inside, Outside).
  • **Z-Buffer Algorithm (Catmull)**: Uses two buffers — a Frame Buffer (initialized to background color) and a Z-Buffer (initialized to max depth `z = ∞` or `1.0`)
  • for each polygon pixel `(x,y,z)`, if `z < Z_buffer[x][y]`, update both buffers!
  • **Painter's Algorithm (Depth-Sorting)** combines Object-Space and Image-Space by sorting surfaces back-to-front.
✅ Direct Exam Example: Z-Buffer Pros & Cons: Requires no pre-sorting of polygons and handles arbitrary intersecting surfaces in hardware GPU pipelines, but requires extra depth memory and cannot handle transparent surfaces without alpha sorting.

📖 Chapter 6: Curves & Shading — Bezier & B-Spline Curves, Phong Illumination Model & Polygon Shading (Flat, Gouraud, Phong)

8 Questions in Booklet
📌 6.1 Bezier & B-Spline Curves, Phong Illumination Model & Polygon Shading (Flat, Gouraud, Phong)
Key Formulas & Rules
  • 🔹 Bezier Curve of n+1 Control Points (P_0..P_n) has Polynomial Degree = n
  • 🔹 Blending Functions B_(k,n)(u) = C(n,k) · u^k · (1 − u)^(n−k) for u ∈ [0,1]
Simple Exam Points
  • Properties of **Bezier Curves** (Pierre Bézier): (1) A Bezier curve defined by `m = n + 1` control points is a polynomial of degree `n = m − 1` (e.g., 4 control points define a **Cubic Bezier Curve of degree 3**)
  • (2) Passes ALWAYS through the **first control point `P_0`** and **last control point `P_n`**
  • (3) Tangent at `P_0` is along `P_1 − P_0` and at `P_n` is along `P_n − P_(n-1)`
  • (4) Lies entirely within the **Convex Hull** of its control points
  • (5) Exhibits **Global Control** (moving any single control point changes the shape of the entire curve!).
  • **B-Spline Curves** overcome this by providing **Local Control** and allowing degree specification independent of the number of control points!
  • Polygon Shading Models: (1) **Constant / Flat Shading** (1 normal evaluation per polygon -> faceted look, Mach band effect)
  • (2) **Gouraud Shading (Intensity-Interpolation)**: Evaluates lighting at polygon vertices and linearly interpolates pixel intensities across scanlines (eliminates sharp discontinuities, misses specular highlights inside polygon)
  • (3) **Phong Shading (Normal-Vector Interpolation)**: Linearly interpolates vertex normal vectors across each pixel and evaluates Phong lighting per pixel (produces realistic sharp Specular Highlights, most computationally expensive).
✅ Direct Exam Example: Phong Illumination Components: `I_total = I_ambient (K_a · I_a) + I_diffuse (K_d · I_l · (N · L) — Lambert's Cosine Law for matte surfaces) + I_specular (K_s · I_l · (R · V)^n — shiny mirror highlight)`.
💡 Exam Shortcut / Trap: Exam Trap: **Bezier Curve** me agar **4 Control Points** diye hain, to curve ki polynomial **Degree = 4 − 1 = 3 (Cubic)** hogi! Aur **Gouraud Shading** *Intensity* interpolate karta hai, jabki **Phong Shading** *Normal Vectors* interpolate karta hai!

Key Formulas & Rules

  • 🔹 CD Audio = 44,100 Hz × 16 bits × 2 stereo = 1,411.2 kbps (~10.5 MB per minute)
Simple Exam Points

✅ Direct Exam Example: Morphing vs Tweening in Animation: **Tweening (In-betweening)** generates intermediate frames between two keyframes of the same object to create smooth motion; **Morphing (Metamorphosis)** smoothly transforms one distinct image/shape into another via mesh warping + cross-dissolve.
