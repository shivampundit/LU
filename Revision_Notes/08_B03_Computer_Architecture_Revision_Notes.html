📖 Chapter 1: Generations & History — Five Generations of Computers, Von Neumann vs Harvard Architecture & Bus Lines

22 Questions in Booklet
📌 1.1 Five Generations of Computers, Von Neumann vs Harvard Architecture & Bus Lines
Key Formulas & Rules
  • 🔹 Address Bus (k bits, Unidirectional) -> Max Addressable Memory = 2^k words
  • 🔹 Data Bus (w bits, Bidirectional) -> Word Size
  • 🔹 Control Bus -> Read/Write/IRQ Timing
Simple Exam Points
  • Computer Generations Hardware & Software: 1st Gen (1940–56: Vacuum Tubes / Thermionic Valves, Magnetic Drums, Machine/Assembly language — ENIAC, EDVAC, UNIVAC-I)
  • 2nd Gen (1956–63: Discrete Transistors, Magnetic Core Memory, FORTRAN/COBOL, Batch OS — IBM 1401/7094)
  • 3rd Gen (1964–71: SSI/MSI Integrated Circuits by Kilby & Noyce, Multiprogramming/Time-sharing — IBM System/360, PDP-8)
  • 4th Gen (1971–Present: LSI/VLSI Microprocessors, Intel 4004 by Ted Hoff, Semiconductor RAM, GUI/LAN — IBM PC, Cray-1)
  • 5th Gen (ULSI, AI, Parallel Processing, Quantum/Superconductors).
  • Von Neumann Architecture (IAS computer) shares a single memory and bus for both instructions and data (causing the Von Neumann bottleneck), whereas Harvard Architecture (DSPs, microcontrollers) uses physically separate memories and buses for instructions and data.
✅ Direct Exam Example: Worked Memory Addressing: A microprocessor has a 24-bit address bus and a 32-bit data bus. Maximum byte-addressable physical memory = 2^24 Bytes = 16 MB, and it transfers 32 bits (4 Bytes) per bus cycle.
💡 Exam Shortcut / Trap: Hinglish Tip: Address Bus hamesha Unidirectional (CPU -> Memory/IO) hoti hai, jabki Data Bus Bidirectional hoti hai! Agar memory 64K × 16 bit ki hai, to 64K = 2^16 => 16 Address lines aur 16 Data lines hongi!

(B) 1st: Transistors, 2nd: Vacuum Tubes, 3rd: VLSI
(C) 1st: ICs, 2nd: Transistors, 3rd: Vacuum Tubes

Answer (A): 1st Gen (1940–56): Vacuum Tubes (ENIAC); 2nd (1956–63): Transistors; 3rd (1964–71): Integrated Circuits (Jack Kilby); 4th (1971+): VLSI Microprocessors (Intel 4004); 5th: ULSI & AI.

(A) Alan Turing
(B) John von Neumann ✅
(C) Charles Babbage
(D) Blaise Pascal
Answer (B): John von Neumann (1945 IAS Architecture) — Von Neumann architecture uses a single shared memory and bus for both instructions and data (Harvard architecture uses separate instruction and data memories).
Q1.3: What is the 'Von Neumann Bottleneck' in computer architecture?
(A) The small size of the keyboard buffer
(B) Overheating of the power supply
(C) The limited data transfer rate over the single shared bus between the CPU and Main Memory ✅
(D) Slow rotation of the cooling fan
Answer (C): Because instructions and data contend for the same single system bus, CPU speed is bottlenecked by memory bus bandwidth.
Q1.4: What is the key difference between a Hardwired Control Unit and a Microprogrammed Control Unit?
(A) Hardwired is slower than Microprogrammed
(B) Microprogrammed is used only in RISC CPUs
(C) Hardwired uses magnetic tape
(D) Hardwired uses fast fixed logic gates ✅
Answer (D): Hardwired uses fast fixed logic gates; Microprogrammed stores control words in Control ROM. Hardwired uses fast fixed logic gates (used in RISC); Microprogrammed stores control words in Control ROM (flexible, used in CISC) — Hardwired Control is faster (combinational hardware), whereas Microprogrammed Control (Wilkes) fetches microinstructions from Control Memory.
Q1.5: In a Microprogrammed Control Unit, which format uses long unencoded microinstructions (1 bit per control line) for maximum parallelism and zero decoder delay?
(A) Horizontal Microprogramming ✅
(B) Vertical Microprogramming (short encoded fields using decoders)
(C) Diagonal Microprogramming
(D) Serial Microprogramming
Answer (A): Horizontal = wide unencoded word, no decoder needed; Vertical = narrow encoded word, requires decoders.

📖 Chapter 2: Memory Hierarchy & Cache — Memory Hierarchy, Locality of Reference, EMAT & Cache Mapping (Direct, Associative, Set-Associative)

22 Questions in Booklet
📌 2.1 Memory Hierarchy, Locality of Reference, EMAT & Cache Mapping (Direct, Associative, Set-Associative)
Key Formulas & Rules
  • 🔹 EMAT = h · t_cache + (1 − h) · t_main (Simultaneous) OR h · t_cache + (1 − h)(t_cache + t_main) (Hierarchical)
  • 🔹 Physical Address (n bits) = [Tag | Index | Block Offset]
Simple Exam Points
  • Speed Order (Fastest to Slowest): CPU Registers -> L1/L2/L3 SRAM Cache (6-transistor flip-flop cell, needs no refreshing) -> Main Memory DRAM (1-transistor + 1-capacitor cell, needs periodic refresh every ~64 ms) -> SSD (NAND Flash) -> Magnetic Disk -> Magnetic Tape.
  • Cache Mapping of M = 2^n Byte main memory with block size B = 2^b Bytes and C = 2^c cache lines: (1) Direct Mapping: Line = (Block Number) mod C -> Offset = b bits, Index = c bits, Tag = (n − c − b) bits
  • (2) Fully Associative: Any block anywhere -> Offset = b bits, Index = 0, Tag = (n − b) bits
  • (3) k-Way Set-Associative (S = C / k = 2^s sets): Set = (Block Number) mod S -> Offset = b bits, Set Index = s bits, Tag = (n − s − b) bits.
✅ Direct Exam Example: Worked Cache Mapping Math: Main Memory = 4 GB (2^32 B -> 32-bit address), Cache Size = 64 KB (2^16 B), Block Size = 64 B (2^6 B -> 6-bit Offset). Number of Cache Lines = 2^16 / 2^6 = 2^10 (1024 lines). In 4-Way Set-Associative Mapping, Number of Sets = 1024 / 4 = 256 = 2^8 -> Set Index = 8 bits, Block Offset = 6 bits, and Tag = 32 − 8 − 6 = 18 bits! Total Tag Directory Memory = 1024 lines × 18 bits = 18 Kb.
💡 Exam Shortcut / Trap: Exam Trap: Direct Mapping se k-way Set-Associative me जाने पर Set count k guna kam hota hai, isliye Set Index me log2(k) bits KAM lagte hain aur Tag field me log2(k) bits ZYADA lagte hain!

📝 Chapter 2 — Practice Questions & Simple Explanations

Q2.1: When does a 'Structural Hazard' occur in a pipelined CPU, and how does Harvard architecture (separate I-Cache and D-Cache) prevent it?
(A) When an instruction divides by zero
(B) When two instructions read the same register
(C) When two instructions in different stages need the SAME hardware unit in the same clock cycle ✅
(D) When a branch is not taken
Answer (C): When two instructions in different stages need the SAME hardware unit in the same clock cycle (e.g., IF fetching an instruction while MEM reads data from a single unified memory) — Having separate Level-1 Instruction Cache (I-Cache) and Data Cache (D-Cache) allows IF and MEM to access memory simultaneously without a Structural Hazard.
Q2.2: Arrange the following computer memories in order from FASTEST (smallest capacity, highest cost/bit) to SLOWEST (largest capacity, lowest cost/bit):
(A) Main Memory -> Cache -> CPU Registers -> Hard Disk
(B) Hard Disk -> Main Memory -> Cache -> Registers
(C) Cache -> Registers -> Hard Disk -> Main Memory
(D) CPU Registers -> L1/L2/L3 Cache (SRAM) -> Main Memory (DRAM) -> SSD / Magnetic Hard Disk -> Magnetic Tape ✅
Answer (D): Memory hierarchy trades off speed vs capacity based on Locality of Reference.
Q2.3: What are the two fundamental principles of 'Locality of Reference' that make Cache Memory achieve >90% hit ratios?
(A) Temporal Locality and Spatial Locality ✅
(B) Static Locality and Dynamic Locality
(C) Random Locality and Sequential Locality
(D) Horizontal and Vertical Locality
Answer (A): Temporal Locality (recently accessed item will be accessed again soon, e.g., loops) and Spatial Locality (nearby memory addresses will be accessed soon, e.g., arrays) — Temporal locality justifies keeping recently accessed blocks in cache; Spatial locality justifies fetching an entire multi-word Cache Block (Line) at once.
Q2.4: If a Cache has a Hit Ratio `h = 0.90` (90%), Cache access time `t_c = 2 ns`, and Main Memory access time (miss penalty) `t_m = 50 ns`, what is the hierarchical Average Memory Access Time (`AMAT = t_c + (1 − h) × t_m`)?
(A) 5.0 ns
(B) 7.0 ns ✅
(C) 6.8 ns
(D) 52.0 ns
Answer (B): 7.0 ns (2 + 0.10 × 50) — `AMAT = Hit_Time + Miss_Rate × Miss_Penalty = 2 + (0.10 × 50) = 7.0 ns` (in simultaneous lookup: `0.9×2 + 0.1×50 = 6.8 ns`).
Q2.5: In Direct-Mapped Cache, if Main Memory block number is `B` and the Cache has `L` lines (`0` to `L − 1`), to which exact cache line can block `B` map?
(A) Any line in the entire cache
(B) Any of k lines in a set
(C) Cache Line = B mod L (only 1 fixed line) ✅
(D) Line 0 only
Answer (C): Direct mapping (`Line = Block_Number mod Total_Cache_Lines`) is simplest and fastest to search (1 tag comparator), but has the highest Conflict Misses.

📖 Chapter 3: CPU & Instruction Cycle — CPU Registers (PC, IR, MAR, MBR, PSW), Instruction Cycle & Hardwired vs Microprogrammed Control

7 Questions in Booklet
📌 3.1 CPU Registers (PC, IR, MAR, MBR, PSW), Instruction Cycle & Hardwired vs Microprogrammed Control
Key Formulas & Rules
  • 🔹 Fetch Micro-Operations: T1: MAR <- (PC)
  • 🔹 T2: MBR <- M[MAR], PC <- PC + 1
  • 🔹 T3: IR <- (MBR)
  • 🔹 Control Word = Microinstruction in Control Memory (ROM)
Simple Exam Points
  • Special-Purpose CPU Registers: Program Counter (PC — holds memory address of the NEXT instruction to be fetched), Instruction Register (IR — holds the currently executing instruction opcode/operands), Memory Address Register (MAR — drives the address bus), Memory Buffer/Data Register (MBR/MDR — interfaces with the data bus), Accumulator (AC — primary ALU operand/result register), Program Status Word (PSW / Flag Register — holds Z, C, S, V, P condition flags).
  • Control Unit Design: Hardwired Control (combinational logic gates/PLA, ultra-fast, fixed instruction set, used in RISC) vs Microprogrammed Control (Wilkes, stores microinstructions in Control ROM with Control Address Register CAR
  • flexible, easy to modify, used in CISC).
✅ Direct Exam Example: Horizontal vs Vertical Microprogramming: Horizontal uses unencoded control bits (1 bit per control line -> long microinstruction word, maximum parallelism, zero decoder delay); Vertical uses encoded k-bit fields decoded via k-to-2^k decoders (short microinstruction word, slower due to decoder delay).
💡 Exam Shortcut / Trap: Hinglish Tip: PC (Program Counter) hamesha AGLE (NEXT) execute hone wale instruction ka address rakhta hai, jabki IR (Instruction Register) CURRENTLY execute ho rahe instruction ka code rakhta hai!

📝 Chapter 3 — Practice Questions & Simple Explanations

Q3.1: Which CPU register holds the memory address of the NEXT instruction to be fetched from main memory?
(A) Program Counter (PC) ✅
(B) Instruction Register (IR)
(C) Memory Address Register (MAR)
(D) Accumulator (AC)
Answer (A): The Program Counter (PC) always points to the address of the next instruction to be executed.
Q3.2: Which CPU register holds the binary opcode of the instruction currently being decoded and executed?
(A) Program Counter (PC)
(B) Instruction Register (IR) ✅
(C) Memory Buffer Register (MBR)
(D) Stack Pointer (SP)
Answer (B): Once fetched from memory via MBR, the instruction is loaded into the Instruction Register (IR) for decoding.
Q3.3: During the instruction Fetch Cycle, what is the correct micro-operation sequence?
(A) IR <- PC; MAR <- MBR
(B) PC <- MAR; MBR <- IR
(C) MAR <- PC; MBR <- M[MAR] & PC <- PC + 1; IR <- MBR ✅
(D) AC <- PC; IR <- MAR
Answer (C): First PC is copied to MAR, memory word is read into MBR while PC increments, and MBR is transferred to IR.
Q3.4: Which register in the CPU points to the current top of the runtime system stack in memory?
(A) Program Counter (PC)
(B) Base Register
(C) Index Register
(D) Stack Pointer (SP) ✅
Answer (D): The Stack Pointer (SP) tracks the top address of the stack during PUSH, POP, and subroutine CALL/RET.
Q3.5: In the CPU Status Register (PSW / Flag Register), which flag is set to 1 when an arithmetic operation produces a result of all zeros?
(A) Zero Flag (Z = 1) ✅
(B) Carry Flag (CY)
(C) Sign Flag (S)
(D) Overflow Flag (V)
Answer (A): Z = 1 when the ALU output is 0; S = 1 when MSB is 1 (negative); CY = 1 on unsigned carry-out; V = 1 on signed 2's complement overflow.

📖 Chapter 4: Addressing Modes — Addressing Modes & Zero-, One-, Two-, Three-Address Instruction Formats

17 Questions in Booklet
📌 4.1 Addressing Modes & Zero-, One-, Two-, Three-Address Instruction Formats
Key Formulas & Rules
  • 🔹 Effective Address (EA): Immediate (No EA, operand in instruction)
  • 🔹 Direct (EA = A)
  • 🔹 Indirect (EA = M[A])
  • 🔹 Register Indirect (EA = [R])
  • 🔹 PC-Relative (EA = PC + Offset)
Simple Exam Points
  • Instruction Formats by CPU Organization: Zero-Address (Stack-organized CPU: PUSH A, PUSH B, ADD — uses TOS implicitly), One-Address (Accumulator-based CPU: LOAD A, ADD B, STORE C), Two-Address (General Register: MOV R1, R2
  • ADD R1, R2), Three-Address (RISC Register-to-Register: ADD R1, R2, R3).
  • Key Addressing Modes & Use Cases: Immediate (loading constants `MOV R1, #50` — 0 memory references during execution), Register Direct (fastest operand access), Indexed (array element traversal `EA = Base + Index`), Base-Register (program relocation in multiprogramming), PC-Relative (position-independent branch instructions), Auto-Increment/Decrement (stack push/pop and loop pointers).
✅ Direct Exam Example: Expanding Opcode Technique: If a 16-bit instruction has 4-bit register fields (3 registers = 12 bits), and supports fourteen 3-address instructions, how many 2-address instructions can it support? Unused 4-bit opcodes = 16 − 14 = 2. Each unused 3-address opcode expands into 2^4 = 16 combinations for the freed 4-bit field => 2 × 16 = 32 two-address instructions!
💡 Exam Shortcut / Trap: Exam Trap: Position-independent code aur Branch instructions ke liye 'PC-Relative Addressing' use hota hai, Array traversal ke liye 'Indexed Addressing', aur Program Relocation ke liye 'Base-Register Addressing'!

(A) Direct Addressing Mode
(B) Indirect Addressing Mode
(C) Indexed Addressing Mode
(D) Immediate Addressing Mode ✅

(B) Indexed Addressing Mode ✅
(C) Immediate Addressing Mode
(D) Direct Addressing Mode
Answer (B): Indexed (and Auto-Increment) mode steps sequentially through array elements by incrementing the index register.

(C) Implied Addressing Mode ✅
(D) Indexed Addressing Mode

Q4.5: What is the key characteristic of RISC (Reduced Instruction Set Computer) compared to CISC (Complex Instruction Set Computer)?

📖 Chapter 5: Data Rep & IEEE 754 — IEEE 754 Floating-Point Standard (Single 32-bit & Double 64-bit) & Endianness

0 Questions in Booklet
📌 5.1 IEEE 754 Floating-Point Standard (Single 32-bit & Double 64-bit) & Endianness
Key Formulas & Rules
  • 🔹 Single Precision (32-bit): 1 Sign + 8 Biased Exponent (Bias +127) + 23 Fractional Mantissa
  • 🔹 Value = (−1)^S × (1.M)_2 × 2^(E − 127)
  • 🔹 Double (64-bit): 1 + 11 (Bias +1023) + 52
Simple Exam Points
  • In normalized IEEE 754 numbers, a hidden leading '1.' is assumed before the 23-bit fraction M (giving 24 bits of effective precision).
  • Special IEEE 754 patterns: (1) E=0, M=0 -> Exact Zero (±0)
  • (2) E=0, M≠0 -> Denormalized number (−1)^S × (0.M) × 2^(−126)
  • (3) E=255 (all 1s), M=0 -> ±Infinity (±∞)
  • (4) E=255, M≠0 -> NaN (Not a Number, e.g., 0/0 or √−1).
  • Endianness: Big-Endian (network byte order, stores MSB at lowest memory address) vs Little-Endian (Intel x86, stores LSB at lowest memory address).
✅ Direct Exam Example: Worked IEEE 754 Conversion: Represent −13.25 in 32-bit IEEE 754. Sign S = 1 (negative). 13.25 in binary = 1101.01_2 = 1.10101 × 2^3. Biased Exponent E = 3 + 127 = 130 = (10000010)_2. Mantissa M = 10101000000000000000000. Hex = 1 10000010 1010100... = 0xC1540000.
💡 Exam Shortcut / Trap: Hinglish Tip: IEEE 754 Single Precision (32-bit) me Bias = 127 hota hai (1 + 8 + 23 bits), aur Double Precision (64-bit) me Bias = 1023 hota hai (1 + 11 + 52 bits)! Normalized form me '1.' implicit (hidden bit) hota hai.

📖 Chapter 6: Pipelining & Hazards — Instruction Pipelining, Speedup, CPI, Hazards (Structural, Data, Control) & Amdahl's Law

10 Questions in Booklet
📌 6.1 Instruction Pipelining, Speedup, CPI, Hazards (Structural, Data, Control) & Amdahl's Law
Key Formulas & Rules
  • 🔹 Pipeline Execution Time for n tasks in k stages = (k + n − 1) × τ
  • 🔹 Ideal Asymptotic Speedup S_max = k
  • 🔹 Effective CPI = 1 + Stall Cycles per Instruction
  • 🔹 Amdahl's Law: S = 1 / ((1 − f) + f / s)
Simple Exam Points
  • Classic 5-Stage RISC Pipeline: IF (Instruction Fetch) -> ID (Instruction Decode & Register Read) -> EX (ALU Execute / Effective Address) -> MEM (Data Memory Access) -> WB (Register Write-Back).
  • Three Pipeline Hazards: (1) Structural Hazard (hardware resource conflict, e.g., unified memory accessed by IF and MEM simultaneously — solved by Harvard split I-Cache/D-Cache)
  • (2) Data Hazard (RAW — Read After Write true dependency
  • WAR — Write After Read anti-dependency
  • WAW — Write After Write output dependency — RAW solved by Operand Forwarding / Bypassing, WAR & WAW solved by Register Renaming)
  • (3) Control / Branch Hazard (pipeline stall on conditional branches — solved by Branch Prediction, Delayed Branch slot).
✅ Direct Exam Example: Worked Pipeline Numerical: A 5-stage pipeline has stage delays 15, 20, 25, 20, 10 ns and latch delay 5 ns. Pipeline clock cycle τ = max(stage) + latch = 25 + 5 = 30 ns. Non-pipelined time = 15+20+25+20+10 = 90 ns. For n = 100 instructions, Pipelined time = (5 + 100 − 1) × 30 = 104 × 30 = 3120 ns.
💡 Exam Shortcut / Trap: Exam Trap: Sirf RAW (Read After Write) hi 'True Data Dependency' hai; WAR (Anti-dependency) aur WAW (Output dependency) 'Name Dependencies' hain jinhe Register Renaming se 100% khatam kiya ja sakta hai!

📝 Chapter 6 — Practice Questions & Simple Explanations

Q6.1: In a k-stage pipeline with clock cycle time τ, how many clock cycles are required to execute 'n' instructions (assuming no stalls)?
(A) k + (n − 1) clock cycles ✅
(B) k × n clock cycles
(C) n / k clock cycles
(D) k + n clock cycles
Answer (A): The first instruction takes `k` cycles to fill the pipeline, and the remaining `(n − 1)` instructions finish at 1 per cycle => `k + n − 1` cycles.
Q6.2: As the number of instructions `n -> ∞`, what is the theoretical maximum (ideal) Speedup of a balanced `k-stage` pipeline over an equivalent non-pipelined processor?
(A) 2k
(B) k (equal to the number of pipeline stages) ✅
(C) k²
(D) log₂(k)
Answer (B): Ideal speedup `S_max = k` when all `k` stages have equal delay and zero hazards/stalls occur.
Q6.3: What are the three types of Pipeline Hazards that cause pipeline stalls (bubbles)?
(A) 1. Voltage, 2. Current, and 3. Resistance Hazards
(B) 1. Compiler, 2. Linker, and 3. Loader Hazards
(C) 1. Structural Hazards, 2. Data Hazards (RAW/WAR/WAW), and 3. Control (Branch) Hazards ✅
(D) 1. Syntax, 2. Runtime, and 3. Logical Hazards
Answer (C): 1. Structural Hazards (resource conflict), 2. Data Hazards (RAW/WAR/WAW), and 3. Control (Branch) Hazards — Structural = hardware resource busy; Data = operand dependency; Control = conditional branch changes PC.
Q6.4: In instruction sequence `I1: ADD R1, R2, R3` (`R1 <- R2 + R3`) followed by `I2: SUB R4, R1, R5` (`R4 <- R1 − R5`), which Data Hazard occurs on `R1`?
(A) WAR (Write-After-Read — Anti-Dependency)
(B) WAW (Write-After-Write — Output Dependency)
(C) Control Hazard
(D) RAW (Read-After-Write — True Data Dependency) ✅
Answer (D): `I2` tries to read `R1` before `I1` has written its result back to `R1` in the WB stage (`RAW` hazard).
Q6.5: Which hardware technique resolves a simple ALU-to-ALU `RAW` data hazard without inserting pipeline stall cycles?
(A) Operand Forwarding (or Bypassing) ✅
(B) Flushing the entire pipeline
(C) Slowing down the clock
(D) Rebooting the CPU
Answer (A): Operand Forwarding feeds the ALU output latch (EX/MEM) directly back into the ALU input for the next instruction.

📖 Chapter 7: I/O & DMA Organization — I/O Organization — Programmed I/O, Interrupt-Driven I/O (Vectored/Daisy Chain) & DMA

7 Questions in Booklet
📌 7.1 I/O Organization — Programmed I/O, Interrupt-Driven I/O (Vectored/Daisy Chain) & DMA
Key Formulas & Rules
  • 🔹 DMA Transfer Modes: Burst / Block Mode (CPU halted for entire block)
  • 🔹 Cycle Stealing Mode (DMA steals 1 bus cycle per word)
  • 🔹 Transparent / Interleaved Mode (DMA uses bus only when CPU is idle)
Simple Exam Points
  • In Programmed I/O (Polling), the CPU continuously busy-waits checking the device status flag (wasting 100% CPU cycles).
  • In Interrupt-Driven I/O, the device asserts the INTR line when ready
  • the CPU completes its current instruction, saves PC & PSW on stack, sends INTA, and jumps to the Interrupt Service Routine (ISR) via an Interrupt Vector Table (Vectored Interrupt) or Daisy-Chaining (serial hardware priority).
  • For high-speed bulk transfers (Disk/Network), Direct Memory Access (DMA Controller, e.g., Intel 8237/8257) takes bus mastership via HOLD and HLDA control signals to transfer data directly between I/O and Main Memory without routing through CPU registers.
✅ Direct Exam Example: Non-Maskable vs Maskable Interrupts: NMI (e.g., TRAP in 8085, power failure, memory parity error) has the highest priority and cannot be disabled by software `CLI/DI` instructions; Maskable interrupts (INTR) can be enabled/disabled via the Interrupt Enable flag.
💡 Exam Shortcut / Trap: Hinglish Tip: DMA Controller CPU se bus control mangne ke liye 'HOLD' signal bhejta hai, aur CPU bus release karke 'HLDA' (Hold Acknowledge) signal wapas deta hai! Interrupt hamesha CURRENT instruction poora hone ke baad hi check hota hai.

📝 Chapter 7 — Practice Questions & Simple Explanations

Q7.1: Among the three I/O data transfer techniques — (1) Programmed I/O (Polling), (2) Interrupt-Driven I/O, and (3) Direct Memory Access (DMA) — which one wastes the MOST CPU cycles waiting in a busy loop, and which is best for high-speed bulk disk/network block transfers?
(A) DMA wastes the most CPU cycles
(B) Programmed I/O is best for 10 Gbps disk transfers
(C) Programmed I/O wastes the most CPU cycles ✅
(D) Interrupt-Driven I/O transfers blocks without the CPU
Answer (C): Programmed I/O wastes the most CPU cycles; DMA is best for high-speed bulk block transfers. In Programmed I/O, the CPU continuously polls the device status bit; in DMA, a dedicated DMA Controller transfers blocks directly between I/O and RAM without involving the CPU for each byte.
Q7.2: What is 'Cycle Stealing' mode in DMA data transfer compared to 'Burst Mode'?
(A) Cycle Stealing locks out the CPU for 10 seconds
(B) Burst Mode transfers only 1 bit per hour
(C) Both modes are identical
(D) In Cycle Stealing, the DMA controller steals one single memory bus cycle at a time to transfer one word and immediately returns bus control to the CPU ✅
Answer (D): In Cycle Stealing, the DMA controller steals one single memory bus cycle at a time to transfer one word and immediately returns bus control to the CPU; in Burst Mode, DMA holds the bus for the entire multi-word block transfer. Cycle Stealing interleaves DMA transfers with CPU operations, whereas Burst Mode maximizes I/O throughput by holding the bus until the whole block is transferred.
Q7.3: What is the difference between a 'Maskable Interrupt' (`INTR`) and a 'Non-Maskable Interrupt' (`NMI`, e.g., TRAP in 8085)?
(A) Maskable interrupts can be temporarily disabled/ignored by the CPU, whereas Non-Maskable Interrupts (`NMI`) have highest priority and CANNOT be disabled by software ✅
(B) Non-Maskable Interrupts can be disabled by the programmer
(C) Maskable Interrupts have higher priority than NMI
(D) NMI is used for normal mouse movement
Answer (A): Maskable interrupts can be temporarily disabled/ignored by the CPU (via Interrupt Enable flag `CLI/DI`), whereas Non-Maskable Interrupts (`NMI`) have highest priority and CANNOT be disabled by software (used for power failure/hardware parity errors) — NMI (like `TRAP` in 8085) handles critical emergencies (power fail, memory parity crash) and can never be masked.
Q7.4: What is 'Vectored Interrupt' vs 'Non-Vectored (Polled) Interrupt'?
(A) Non-Vectored Interrupt is faster than Vectored Interrupt
(B) In a Vectored Interrupt, the interrupting device itself supplies a unique Interrupt Vector directly to the CPU ✅
(C) Vectored Interrupt requires polling all devices in software
(D) Vectored Interrupt does not use an ISR
Answer (B): In a Vectored Interrupt, the interrupting device itself supplies a unique Interrupt Vector directly to the CPU; in a Non-Vectored Interrupt, the CPU jumps to a single fixed address and polls devices to find who interrupted. In a Vectored Interrupt, the interrupting device itself supplies a unique Interrupt Vector (starting address of its ISR) directly to the CPU; in a Non-Vectored Interrupt, the CPU jumps to a single fixed address and polls devices to find who interrupted — Vectored interrupts eliminate software polling latency by jumping directly to the device's Interrupt Service Routine (ISR) via the Interrupt Vector Table (IVT).
Q7.5: During a Direct Memory Access (DMA) block transfer, when the DMA controller steals single memory bus cycles from the CPU to transfer one word at a time while the CPU continues internal register operations, this mode is called:
(A) Burst (Block Transfer) Mode
(B) Programmed Polling I/O
(C) Cycle Stealing Mode ✅
(D) Vectored Interrupt Mode
Answer (C): In Burst mode, the DMA controller holds the system bus for the entire block transfer; in Cycle Stealing mode, it takes single bus cycles periodically, slowing the CPU slightly without blocking it completely.
