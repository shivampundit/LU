📖 Chapter 1: Internet & HTTP Basics — World Wide Web Architecture, URI/URL Anatomy, HTTP Methods (GET/POST/PUT/DELETE) & Status Codes

2 Questions in Booklet
📌 1.1 World Wide Web Architecture, URI/URL Anatomy, HTTP Methods (GET/POST/PUT/DELETE) & Status Codes
Key Formulas & Rules
  • 🔹 HTTP Status Codes: 1xx (Informational)
  • 🔹 2xx (Success: 200 OK, 201 Created)
  • 🔹 3xx (Redirection: 301 Moved Permanently, 304 Not Modified)
  • 🔹 4xx (Client Error: 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found)
  • 🔹 5xx (Server Error: 500 Internal, 502 Bad Gateway, 503 Unavailable)
Simple Exam Points
  • HTTP is a stateless request-response protocol.
  • Idempotency & Safety of HTTP Methods: `GET` and `HEAD` are both SAFE (read-only) and IDEMPOTENT (executing N times has the same server state effect as executing once)
  • `PUT` (replaces target resource) and `DELETE` are IDEMPOTENT (not safe)
  • `POST` (creates subordinate resource / submits form body) is NEITHER safe NOR idempotent!
  • `GET` appends URL-encoded parameters to the query string (limited to ~2048 chars, visible in browser history/logs, bookmarkable), whereas `POST` sends parameters inside the HTTP message body (supports `multipart/form-data` binary file uploads).
✅ Direct Exam Example: Idempotent HTTP Methods Set: `GET`, `HEAD`, `PUT`, `DELETE`, `OPTIONS`, `TRACE` are Idempotent; `POST` and `PATCH` are Non-Idempotent.
💡 Exam Shortcut / Trap: Hinglish Tip: HTTP Status Codes: `301` = Permanent Redirect, `304` = Cached (Not Modified), `401` = Unauthenticated (Login needed), `403` = Forbidden (No permission despite login), `404` = Not Found, `500` = Server Crash, `502` = Bad Gateway!

📖 Chapter 2: HTML5 & Semantic Web — HTML5 Semantic Structure, Forms, Multimedia (`<canvas>` vs `<svg>`) & Web Storage APIs

12 Questions in Booklet
📌 2.1 HTML5 Semantic Structure, Forms, Multimedia (`<canvas>` vs `<svg>`) & Web Storage APIs
Key Formulas & Rules
  • 🔹 HTML5 DOCTYPE = `<!DOCTYPE html>`
  • 🔹 `<canvas>` = Resolution-dependent Raster Bitmap (JS pixel drawing) vs `<svg>` = Resolution-independent XML Vector DOM
Simple Exam Points
  • HTML5 Semantic Elements (`<header>`, `<nav>`, `<main>`, `<article>`, `<section>`, `<aside>`, `<footer>`, `<figure>`, `<figcaption>`) improve SEO and screen-reader accessibility over generic `<div>` tags.
  • HTML5 Form Input Types & Attributes: `email`, `url`, `number`, `range`, `date`, `color`, `search`, plus `required`, `placeholder`, `pattern` (regex validation), `autofocus`, and `autocomplete`.
  • Client-Side Storage Comparison: (1) Cookies (4 KB limit, sent with EVERY HTTP request header, supports `HttpOnly`, `Secure`, `SameSite`, and `Expires`)
  • (2) `localStorage` (5–10 MB limit, persists permanently across browser restarts until explicitly cleared, never sent to server)
  • (3) `sessionStorage` (5 MB limit, isolated per browser tab, cleared automatically when the tab closes).
✅ Direct Exam Example: Script Loading Attributes (`<script src="app.js">`): Normal `<script>` pauses HTML parsing to download and execute immediately; `defer` downloads in parallel and executes in order ONLY AFTER HTML parsing finishes (`DOMContentLoaded`); `async` downloads in parallel and executes immediately upon download completion (out-of-order).
💡 Exam Shortcut / Trap: Exam Trap: `<canvas>` pixel-based (Raster) hai jisme JS se draw karne ke baad individual shapes DOM elements nahi bante, jabki `<svg>` XML-based (Vector) hai jisme har shape DOM ka hissa hota hai aur zoom karne par kabhi blur nahi hota!

📖 Chapter 3: CSS3 & Responsive Design — CSS3 Box Model, Specificity Tuple `(a,b,c,d)`, Positioning & Flexbox vs CSS Grid

8 Questions in Booklet
📌 3.1 CSS3 Box Model, Specificity Tuple `(a,b,c,d)`, Positioning & Flexbox vs CSS Grid
Key Formulas & Rules
  • 🔹 CSS Specificity Tuple: Inline Style `(1,0,0,0)` > `#ID` `(0,1,0,0)` > `.class` / `[attr]` / `:pseudo-class` `(0,0,1,0)` > `element` / `::pseudo-element` `(0,0,0,1)`
  • 🔹 Universal `*` = `(0,0,0,0)`
Simple Exam Points
  • CSS Box Model (from inside out): Content -> Padding -> Border -> Margin.
  • With default `box-sizing: content-box`, rendered width = `width + padding-left + padding-right + border-left + border-right`
  • setting `box-sizing: border-box` includes padding and border INSIDE the declared `width`!
  • CSS Positioning: `static` (default, ignores top/left/z-index), `relative` (offset relative to its own normal position, retains space in flow), `absolute` (removed from flow, positioned relative to nearest non-static positioned ancestor!), `fixed` (positioned relative to browser viewport), `sticky` (hybrid relative-then-fixed on scroll).
  • Flexbox (`display: flex`) is 1-dimensional (row OR column: `justify-content` aligns along main axis, `align-items` aligns along cross axis)
  • CSS Grid (`display: grid`) is 2-dimensional (rows AND columns).
✅ Direct Exam Example: Worked Box Model & Specificity Math: An element has `width: 200px; padding: 20px; border: 5px solid black; margin: 10px;` under default `content-box`. Total visible box width (border-to-border) = `200 + 20 + 20 + 5 + 5 = 250px` (and total space with margin = `270px`). Under `border-box`, visible box width is exactly `200px`!
💡 Exam Shortcut / Trap: Hinglish Tip: `box-sizing: border-box` lagane par `padding` aur `border` declared `width` ke ANDAR count hote hain! Aur `position: absolute` hamesha apne sabse kareebi non-static (relative/absolute/fixed) parent ke respect me position leta hai.

📖 Chapter 4: JavaScript & DOM — JavaScript ES6+ Scopes (`var`/`let`/`const`), Closures, Event Bubbling/Capturing & Type Coercion

7 Questions in Booklet
📌 4.1 JavaScript ES6+ Scopes (`var`/`let`/`const`), Closures, Event Bubbling/Capturing & Type Coercion
Key Formulas & Rules
  • 🔹 `var` = Function-scoped, hoisted as `undefined`
  • 🔹 `let` / `const` = Block-scoped `{ }`, Temporal Dead Zone (TDZ)
  • 🔹 `==` (Abstract Coercion) vs `===` (Strict Value + Type)
Simple Exam Points
  • JavaScript Quirks & Type Coercion: `typeof null` returns `"object"` (historical JS bug!), `typeof NaN` returns `"number"`, `NaN === NaN` is `false` (use `Number.isNaN()`), `null == undefined` is `true` but `null === undefined` is `false`.
  • Expression traps: `"5" + 3` -> `"53"` (string concatenation), whereas `"5" - 3` -> `2` (numeric subtraction)!
  • A Closure is a function bundled with its lexical environment, allowing an inner function to access variables of its outer parent function even after the outer function has returned.
  • DOM Event Propagation has 3 phases: (1) Capturing Phase (`window` -> target, enabled via `addEventListener(type, fn, true)`), (2) Target Phase, and (3) Bubbling Phase (target -> `window`, default `false`
  • stopped via `event.stopPropagation()`, default browser action prevented via `event.preventDefault()`).
✅ Direct Exam Example: Event Delegation Pattern: Instead of attaching 1,000 click listeners to 1,000 `<li>` items, attach a SINGLE listener to the parent `<ul>` and inspect `event.target` via Event Bubbling!
💡 Exam Shortcut / Trap: Exam Trap: JavaScript me `typeof null` ka output `"object"` hota hai, aur `typeof NaN` ka output `"number"` hota hai! Event propagation me default phase 'Event Bubbling' (child se parent ki taraf) hota hai.

📖 Chapter 5: Async JS & Web Services — Asynchronous JS (Event Loop, Microtasks vs Macrotasks, Promises, Async/Await), AJAX, JSON & XML

4 Questions in Booklet
📌 5.1 Asynchronous JS (Event Loop, Microtasks vs Macrotasks, Promises, Async/Await), AJAX, JSON & XML
Key Formulas & Rules
  • 🔹 Event Loop Priority: Call Stack -> Microtask Queue (`Promise.then`, `queueMicrotask`, `MutationObserver`) -> Macrotask / Callback Queue (`setTimeout`, `setInterval`, I/O)
Simple Exam Points
  • JavaScript is single-threaded with a non-blocking Event Loop.
  • After the synchronous Call Stack empties, the Event Loop drains ALL pending jobs in the **Microtask Queue** (Promise `.then/.catch/.finally` and `async/await` continuations) BEFORE picking even a single callback from the **Macrotask Queue** (`setTimeout(..., 0)`).
  • A `Promise` has 3 states: `Pending`, `Fulfilled` (Resolved), or `Rejected` (once settled, state is immutable).
  • XML vs JSON: XML supports namespaces, attributes, comments, and XSD/DTD schema validation (`Well-Formed XML` obeys syntax rules like single root element & proper tag nesting
  • `Valid XML` additionally conforms to a DTD or XSD Schema!).
  • SOAP (XML-only, heavy enterprise WSDL/WS-Security over HTTP/SMTP) vs REST (architectural style using stateless HTTP verbs and lightweight JSON/XML).
✅ Direct Exam Example: Worked Event Loop Output: `console.log(1); setTimeout(()=>console.log(2), 0); Promise.resolve().then(()=>console.log(3)); console.log(4);` -> Output order is strictly `1, 4, 3, 2`!
💡 Exam Shortcut / Trap: Hinglish Tip: `setTimeout(fn, 0)` aur `Promise.resolve().then(fn)` me hamesha **Promise (`Microtask Queue`) PEHLE execute hota hai** aur `setTimeout` (`Macrotask Queue`) BAAD me execute hota hai!

📖 Chapter 6: Web Security & Storage — Web Application Security (OWASP Top Risks — SQLi, XSS, CSRF, CORS) & Authentication (JWT/OAuth)

📌 6.1 Web Application Security (OWASP Top Risks — SQLi, XSS, CSRF, CORS) & Authentication (JWT/OAuth)
Key Formulas & Rules
  • 🔹 SQL Injection Defense = Parameterized Queries / Prepared Statements
  • 🔹 XSS Defense = Context-Aware Output Encoding + `Content-Security-Policy (CSP)` + `HttpOnly` Cookie
  • 🔹 CSRF Defense = Anti-CSRF Token + `SameSite=Strict/Lax`
Simple Exam Points
  • Core Web Vulnerabilities & Mitigations: (1) SQL Injection (SQLi): Attacker injects `' OR '1'='1' --` into unparameterized SQL strings
  • prevented 100% by Prepared Statements (`?` placeholders) which compile the SQL execution plan before binding user literals as non-executable data
  • (2) Cross-Site Scripting (XSS — Stored, Reflected, DOM-based): Attacker injects malicious `<script>` into victim's browser to steal session cookies
  • prevented by Output Escaping (`<` -> `&lt;`), `HttpOnly` cookie flag (blocks `document.cookie` access in JS), and CSP headers
  • (3) Cross-Site Request Forgery (CSRF): Tricks an already-authenticated user's browser into sending an unwanted state-changing request
  • prevented by synchronizer Anti-CSRF tokens and `SameSite` cookies.
  • JSON Web Token (JWT) consists of 3 Base64Url-encoded parts separated by dots: `Header.Payload.Signature`.
✅ Direct Exam Example: Same-Origin Policy (SOP) & CORS: Two URLs share the same Origin ONLY if their `Scheme (Protocol)`, `Hostname (Domain)`, AND `Port` match identically (`https://example.com:443`). Cross-Origin Resource Sharing (CORS) uses HTTP headers (`Access-Control-Allow-Origin`) and `OPTIONS` preflight requests.
💡 Exam Shortcut / Trap: Exam Trap: `HttpOnly` cookie flag **XSS** ke jariye `document.cookie` chori hone se bachata hai, jabki `SameSite` cookie flag aur Synchronizer Token **CSRF** attack se bachate hain! Aur SQL Injection ka पक्का इलाज 'Prepared Statements' hai.

📖 Chapter 7: .NET & MVC Architecture — .NET Framework Architecture (CLR, CTS, CLS, MSIL/CIL), ADO.NET & ASP.NET MVC

6 Questions in Booklet
📌 7.1 .NET Framework Architecture (CLR, CTS, CLS, MSIL/CIL), ADO.NET & ASP.NET MVC
Key Formulas & Rules
  • 🔹 Compilation Pipeline: Source Code (C#/VB.NET) -> Language Compiler -> MSIL / CIL Bytecode (`.dll`/`.exe` Assembly) -> CLR JIT Compiler -> Native Machine Code
Simple Exam Points
  • Core .NET Pillars: (1) CLR (Common Language Runtime): Execution engine providing JIT compilation, Garbage Collection (Generational GC: Gen 0 short-lived, Gen 1 buffer, Gen 2 long-lived objects), Code Access Security, and Exception Handling
  • (2) CTS (Common Type System): Divides types into Value Types (allocated on Stack: `int, double, bool, struct, enum`) and Reference Types (allocated on Managed Heap: `class, interface, delegate, string, object`
  • Boxing converts Value Type -> Reference Object on heap
  • Unboxing extracts Value Type from Object with explicit cast)
  • (3) CLS (Common Language Specification): Subset of CTS rules ensuring cross-language interoperability.
  • ADO.NET Architecture: Connected Architecture (`SqlConnection`, `SqlCommand`, `SqlDataReader` — fast, forward-only, read-only stream) vs Disconnected Architecture (`SqlDataAdapter`, `DataSet` — in-memory relational cache of tables/relations).
✅ Direct Exam Example: ASP.NET Web Forms vs ASP.NET MVC: Web Forms uses stateful event-driven controls with hidden `__VIEWSTATE`; ASP.NET MVC (Model-View-Controller) enforces clean separation of concerns, stateless HTTP routing, and unit testability (`ViewBag`, `ViewData`, and `TempData`).
💡 Exam Shortcut / Trap: Hinglish Tip: ADO.NET me `DataReader` **Connected, Forward-Only, Read-Only** fast stream hai, jabki `DataSet` (filled via `DataAdapter`) **Disconnected, In-Memory** relational cache hai! Aur Value Type ko Object me badalna = **Boxing**.
