📖 Chapter 1: Asymptotic Analysis — Asymptotic Notations (Big-O, Ω, Θ, o, ω), Growth Hierarchy & Loop Time Complexity

📌 1.1 Asymptotic Notations (Big-O, Ω, Θ, o, ω), Growth Hierarchy & Loop Time Complexity
Key Formulas & Rules
  • 🔹 Big-O (Upper): 0 <= f(n) <= c·g(n)
  • 🔹 Big-Ω (Lower): f(n) >= c·g(n)
  • 🔹 Big-Θ (Tight): c1·g(n) <= f(n) <= c2·g(n)
  • 🔹 Hierarchy: O(1) < O(log log n) < O(log n) < O(√n) < O(n) < O(n log n) < O(n²) < O(2^n) < O(n!) < O(n^n)
Simple Exam Points
  • Asymptotic notations characterize algorithm scalability as input size n -> ∞.
  • Properties: Transitivity holds for all 5 notations (O, Ω, Θ, o, ω)
  • Symmetry holds ONLY for Θ (f(n) = Θ(g(n)) <=> g(n) = Θ(f(n)))
  • Transpose Symmetry holds between O and Ω (f(n) = O(g(n)) <=> g(n) = Ω(f(n))).
  • Important identity: log(n!) = Θ(n log n) (Stirling's approximation), and Σ_{i=1..n} (n/i) = n · H_n = Θ(n log n).
✅ Direct Exam Example: Worked Complexity Comparison: Compare f(n) = 2^n and g(n) = n^100, or f(n) = (log n)^100 and g(n) = n^0.001. Any positive polynomial n^ε asymptotically dominates any polylogarithmic function (log n)^k, and any exponential 2^n dominates n^k!
💡 Exam Shortcut / Trap: Hinglish Tip: `for(i=1; i<=n; i=i*2)` loop O(log2 n) baar chalta hai; `for(i=2; i<=n; i=i*i)` loop O(log log n) baar chalta hai; aur nested harmonic loop `for(i=1..n) for(j=1; j<=n; j+=i)` O(n log n) time leta hai!

📝 Chapter 1 — Practice Questions & Simple Explanations

Q1.1: Which Asymptotic Notation represents the 'Upper Bound' (worst-case growth rate), 'Lower Bound', and 'Tight Bound' of an algorithm?
(A) Big-O (O) = Upper Bound; Big-Omega (Ω) = Lower Bound; Theta (Θ) = Tight Bound ✅
(B) Big-O = Lower Bound; Omega = Upper Bound
(C) Theta = Strict Upper Bound
(D) All three mean Average Case
Answer (A): Big-O is analogous to `≤`, Big-Omega (Ω) is analogous to `≥`, and Theta (Θ) is analogous to `==`.
Q1.2: Arrange the following time complexities in strictly increasing order of asymptotic growth rate: `O(n), O(1), O(log n), O(n²), O(n log n), O(2^n)`:
(A) O(1) < O(n) < O(log n) < O(n log n) < O(n²) < O(2^n)
(B) O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2^n) ✅
(C) O(log n) < O(1) < O(n) < O(2^n) < O(n²)
(D) O(n²) < O(n log n) < O(2^n)
Answer (B): Constant `O(1)` < Logarithmic `O(log n)` < Linear `O(n)` < Linearithmic `O(n log n)` < Quadratic `O(n²)` < Exponential `O(2^n)` < Factorial `O(n!)`.
Q1.3: What is the time complexity of the nested loop: `for(i=1; i<=n; i = i*2)`?
(A) O(n)
(B) O(n²)
(C) O(log₂ n) ✅
(D) O(√n)
Answer (C): Since `i` doubles (`1, 2, 4, 8, ..., 2^k ≤ n`) at each iteration, the loop executes `⌊log₂ n⌋ + 1 = O(log n)` times.
Q1.4: If an algorithm takes `T(n) = 5n³ + 20n² + 100` operations, what is its tight asymptotic time complexity?
(A) Θ(5n³)
(B) Θ(n²)
(C) Θ(100)
(D) Θ(n³) ✅
Answer (D): Θ(n³) (drop lower-order terms and constant coefficients) — As `n -> ∞`, the highest-degree term `n³` dominates.
Q1.5: What is the time complexity of the harmonic-step nested loop: `for(i=1; i<=n; i++) for(j=1; j<=n; j += i)`?
(A) Θ(n log n) ✅
(B) Θ(n²)
(C) Θ(n)
(D) Θ(log n)
Answer (A): The inner loop runs `n/i` times for `i = 1..n`. Summing `n(1 + 1/2 + 1/3 + ... + 1/n) = n · H_n = Θ(n log n)`.

📖 Chapter 2: Divide and Conquer — Divide & Conquer Recurrences, Master Theorem & Binary Search / Merge / Quick / Strassen

9 Questions in Booklet
📌 2.1 Divide & Conquer Recurrences, Master Theorem & Binary Search / Merge / Quick / Strassen
Key Formulas & Rules
  • 🔹 Master Theorem for T(n) = a·T(n/b) + Θ(n^k · log^p n) (a>=1, b>1): Compare c_crit = log_b(a) vs k: (1) c_crit > k -> Θ(n^(log_b a)); (2) c_crit == k: if p > −1 -> Θ(n^k · log^(p+1) n), if p == −1 -> Θ(n^k · log log n), if p < −1 -> Θ(n^k); (3) c_crit < k -> Θ(n^k · log^p n)
Simple Exam Points
  • Standard Divide-and-Conquer Recurrences: (1) Binary Search: T(n) = T(n/2) + O(1) => Θ(log n)
  • (2) Merge Sort: T(n) = 2T(n/2) + Θ(n) => Θ(n log n) in Best, Average, and Worst cases
  • (3) Quick Sort Best/Avg: T(n) = 2T(n/2) + Θ(n) => Θ(n log n), Worst Case (already sorted array with first/last pivot): T(n) = T(n−1) + Θ(n) => Θ(n²)
  • (4) Karatsuba Fast Multiplication: T(n) = 3T(n/2) + O(n) => Θ(n^log2(3)) = Θ(n^1.585)
  • (5) Strassen's Matrix Multiplication (7 multiplications instead of 8): T(n) = 7T(n/2) + Θ(n²) => Θ(n^log2(7)) = Θ(n^2.81)
  • (6) Binary Tree Traversal / Min-Max tournament: T(n) = 2T(n/2) + O(1) => Θ(n) (with ⌈3n/2⌉ − 2 comparisons for simultaneous Min & Max!).
✅ Direct Exam Example: Worked Master Theorem: Solve T(n) = 4T(n/2) + n² log n. Here a = 4, b = 2 => log_b(a) = log2(4) = 2. Since k = 2 and p = 1 (Case 2 with p > −1), T(n) = Θ(n² · log^(1+1) n) = Θ(n² log² n).
💡 Exam Shortcut / Trap: Exam Trap: Simultaneous Min & Max Using Divide-and-Conquer takes exactly `3n/2 − 2` comparisons (versus `2n − 2` in naive linear scan)! Aur Strassen's Matrix Multiplication 8 ke bajay 7 recursive multiplications use karta hai.

(C) Θ(log n)
(D) Θ(n log n) ✅
Answer (D): Here `a = 2, b = 2 => n^(log_b a) = n¹ = n = f(n)` (Master Theorem Case 2) => `T(n) = Θ(n log n)`.
Q2.2: Using the Master Theorem, what is the time complexity of the Binary Search recurrence `T(n) = T(n/2) + Θ(1)`?
(A) Θ(log n) ✅
(B) Θ(n)
(C) Θ(n log n)
(D) Θ(1)
Answer (A): Here `a = 1, b = 2 => n^(log₂ 1) = n⁰ = 1 = f(n)` (Case 2) => `T(n) = Θ(log n)`.
Q2.3: Under what input condition does Quick Sort experience its Worst-Case time complexity `O(n²)` when choosing the first or last element as the pivot?
(A) When the pivot always lands at the exact median
(B) When the input array is already sorted or all elements are identical ✅
(C) When the array has an even number of elements
(D) Quick Sort never takes O(n²)
Answer (B): When the input array is already sorted (in ascending or descending order) or all elements are identical — An unbalanced partition of `(0)` and `(n − 1)` elements yields `T(n) = T(n − 1) + O(n) = O(n²)`. Randomized pivot or Median-of-Three prevents this.
Q2.4: What is the auxiliary space complexity of standard Merge Sort on an array of `n` elements vs Heap Sort?
(A) Merge Sort = O(1); Heap Sort = O(n)
(B) Both take O(n²) space
(C) Merge Sort = O(n) auxiliary space; Heap Sort = O(1) in-place auxiliary space ✅
(D) Both are O(1) in-place on arrays
Answer (C): Merge Sort requires an `O(n)` temporary array for merging, whereas Heap Sort sorts in-place (`O(1)` extra space).
Q2.5: Using the Master Theorem, what is the solution to the recurrence `T(n) = 4T(n/2) + Θ(n)`?
(A) Θ(n log n)
(B) Θ(n)
(C) Θ(n³)
(D) Θ(n²) ✅
Answer (D): Here `a = 4, b = 2 => n^(log₂ 4) = n² > f(n) = n` (Case 1) => `T(n) = Θ(n²)`.

📖 Chapter 3: Searching & Sorting — Sorting & Searching Master Comparison — Stability, In-Place, Swaps & Decision Tree Lower Bound

14 Questions in Booklet
📌 3.1 Sorting & Searching Master Comparison — Stability, In-Place, Swaps & Decision Tree Lower Bound
Key Formulas & Rules
  • 🔹 Comparison-Based Sorting Lower Bound = Ω(log2(n!)) = Ω(n log n)
  • 🔹 Build-Max-Heap (Bottom-Up) = O(n) (NOT O(n log n)!)
  • 🔹 Counting Sort = O(n + k)
  • 🔹 Radix Sort = O(d(n + k))
Simple Exam Points
  • Comprehensive Sorting Matrix: (1) Bubble Sort: Best O(n) (with flag on sorted input, 0 swaps, n−1 comparisons), Avg/Worst O(n²), Stable, In-place O(1)
  • (2) Insertion Sort: Best O(n) (sorted input), Avg/Worst O(n²), Stable, In-place O(1), fastest for tiny or nearly-sorted arrays (O(n + d) for d inversions)
  • (3) Selection Sort: Best/Avg/Worst ALL Θ(n²) comparisons, but MINIMUM number of swaps in worst case = O(n) (at most n−1 swaps!), Unstable, In-place
  • (4) Merge Sort: Best/Avg/Worst Θ(n log n), Stable, NOT In-place (requires O(n) auxiliary array for arrays, O(1) extra for linked lists)
  • (5) Quick Sort: Best/Avg O(n log n), Worst O(n²), Unstable, In-place (O(log n) recursion stack)
  • (6) Heap Sort: Best/Avg/Worst O(n log n), Unstable, In-place O(1).
✅ Direct Exam Example: Worked Inversion & Heap Check: In a descending array of n elements, total inversions = n(n−1)/2. Bottom-up `Build-Heap` on n elements runs in linear O(n) time, whereas inserting n elements one-by-one into an initially empty heap takes O(n log n) time.
💡 Exam Shortcut / Trap: Hinglish Tip: Stable Sorting Algorithms = Bubble, Insertion, Merge, Counting, Radix ('B-I-M-C-R'); Unstable = Selection, Quick, Heap, Shell! Aur sabse KAM swaps (O(n) max n−1 swaps) Selection Sort karta hai!

Q3.1: What is the Worst-Case and Best-Case time complexity of Binary Search on a sorted array of `n` elements?
(A) Worst Case = O(log n); Best Case = O(1) ✅
(B) Worst Case = O(n); Best Case = O(log n)
(C) Both are O(n)
(D) Worst Case = O(n log n)
Answer (A): Worst Case = O(log n); Best Case = O(1) (when target is at the middle element) — Binary Search halves the search space at each step (`O(log n)` worst case) and takes `O(1)` if the middle element matches first.
Q3.2: Which comparison-based sorting algorithm has the BEST performance `O(n)` on an array that is ALREADY sorted (or nearly sorted)?
(A) Quick Sort (degrades to O(n²) on sorted array with first/last pivot!)
(B) Insertion Sort (and optimized Bubble Sort with a swap flag) ✅
(C) Selection Sort (always takes Θ(n²) comparisons!)
(D) Merge Sort (always takes Θ(n log n))
Answer (B): Insertion Sort makes only `n − 1` comparisons and `0` swaps on an already sorted array (`O(n)` best case).
Q3.3: Which sorting algorithm ALWAYS performs the exact same number of comparisons `n(n − 1)/2 = Θ(n²)` in Best, Average, and Worst cases, but performs the MINIMUM number of data swaps `O(n)`?
(A) Insertion Sort
(B) Bubble Sort
(C) Selection Sort ✅
(D) Quick Sort
Answer (C): Selection Sort always scans the remaining subarray (`Θ(n²)` comparisons) but swaps at most `n − 1` times (`O(n)` swaps).
Q3.4: Which of the following sorting algorithms are STABLE (preserve the relative order of records with equal keys) by default?
(A) Quick Sort and Heap Sort are Stable
(B) Merge Sort is Unstable
(C) Selection Sort is Stable
(D) Bubble Sort, Insertion Sort, Merge Sort, Counting Sort, and Radix Sort ✅
Answer (D): Bubble Sort, Insertion Sort, Merge Sort, Counting Sort, and Radix Sort (whereas Quick Sort, Heap Sort, and Selection Sort are UNSTABLE) — Stable sorts: Bubble, Insertion, Merge, Counting, Radix. Unstable sorts: Quick, Heap, Selection, Shell.
Q3.5: What is the theoretical Lower Bound on the number of comparisons required by ANY comparison-based sorting algorithm in the worst case?
(A) Ω(n log n) (specifically ⌈log₂(n!)⌉ ≈ n log₂ n) ✅
(B) Ω(n)
(C) Ω(n²)
(D) Ω(log n)
Answer (A): Because a comparison decision tree must have at least `n!` leaves for `n` items, its height is at least `log₂(n!) = Θ(n log n)`.

8 Questions in Booklet
📌 4.1 Greedy Paradigm — Fractional Knapsack, Huffman Coding, Job Sequencing & Activity Selection
Key Formulas & Rules
  • 🔹 Fractional Knapsack = Sort by Value/Weight ratio (p_i / w_i) in O(n log n)
  • 🔹 Huffman Tree (n characters) = (n − 1) internal merges in O(n log n)
  • 🔹 Activity Selection = Sort by EARLIEST Finish Time!
Simple Exam Points
  • A Greedy algorithm makes locally optimal choices at each step relying on the Greedy-Choice Property and Optimal Substructure.
  • Key Greedy Algorithms: (1) Fractional Knapsack: Takes items in descending order of profit-to-weight ratio `p_i / w_i` (yields exact global optimum, unlike 0/1 Knapsack where Greedy fails!)
  • (2) Activity Selection / Interval Scheduling: Sort activities in ascending order of FINISH TIME `f_i` (NOT start time or shortest duration!)
  • (3) Huffman Prefix Coding: Variable-length lossless compression using a Min-Heap priority queue (repeatedly merges the 2 lowest-frequency nodes
  • satisfies the Prefix Rule where no codeword is a prefix of another codeword).
✅ Direct Exam Example: Worked Huffman Coding Math: Six characters have frequencies A:5, B:9, C:12, D:13, E:16, F:45 (Total = 100). Merge 5+9=14; Merge 12+13=25; Merge 14+16=30; Merge 25+30=55; Merge 45+55=100. Code lengths: F=1 bit ('0'), C,D,E=3 bits, A,B=4 bits. Average bits/char = (45×1 + (12+13+16)×3 + (5+9)×4)/100 = 2.24 bits/char.
💡 Exam Shortcut / Trap: Exam Trap: Activity Selection problem me optimal Greedy choice 'Earliest Finish Time' (sabse pehle khatam hone wali activity) hoti hai — 'Earliest Start Time' ya 'Shortest Duration' galat answer deta hai!

📝 Chapter 4 — Practice Questions & Simple Explanations

Q4.1: Which algorithmic paradigm is used by (1) Merge Sort & Quick Sort, (2) Kruskal's, Prim's, Dijkstra's & Huffman Coding, and (3) Floyd-Warshall, Bellman-Ford & 0/1 Knapsack?
(A) (1) Greedy, (2) Dynamic Programming, (3) Backtracking
(B) All three use Divide and Conquer
(C) (1) Divide and Conquer, (2) Greedy Method, and (3) Dynamic Programming ✅
(D) 0/1 Knapsack is solved by Greedy Method
Answer (C): Note: **Fractional Knapsack** is solved optimally by the **Greedy Method** (sorting by Value/Weight ratio in `O(n log n)`), whereas **0/1 Knapsack** requires **Dynamic Programming** (`O(n · W)`).
Q4.2: Why does Dijkstra's Single-Source Shortest Path algorithm fail when a graph contains negative-weight edges, and which algorithm handles negative weights?
(A) Dijkstra works on all negative-weight cycles
(B) Bellman-Ford runs in O(log V) time
(C) Prim's algorithm finds shortest paths with negative weights
(D) Dijkstra's greedy assumption fails when a negative edge can reduce an already finalized vertex's distance ✅
Answer (D): Dijkstra's greedy assumption fails when a negative edge can reduce an already finalized vertex's distance; Bellman-Ford (`O(V · E)`) handles negative edge weights and detects negative cycles. Bellman-Ford relaxes all `E` edges `(V − 1)` times (`O(V·E)`). A `V`-th relaxation check detects any reachable negative-weight cycle.
Q4.3: In the Greedy Fractional Knapsack problem, in what order are items selected to maximize total profit?
(A) In decreasing order of their Profit-to-Weight ratio ✅
(B) In decreasing order of weight `w_i`
(C) In increasing order of profit `p_i`
(D) Random order
Answer (A): In decreasing order of their Profit-to-Weight ratio (`p_i / w_i`) — Sorting items by `Value / Weight` ratio takes `O(n log n)` time and gives the exact global optimum for Fractional Knapsack.
Q4.4: In Huffman Coding, if a character set has 5 symbols with frequencies `{5, 9, 12, 13, 16}`, which two frequencies are merged FIRST in the greedy step?
(A) The two largest frequencies: 13 and 16
(B) The two smallest frequencies: 5 and 9 ✅
(C) 5 and 16
(D) 9 and 12
Answer (B): The two smallest frequencies: 5 and 9 (forming a combined internal node of weight 14) — Huffman's greedy algorithm uses a Min-Priority Queue (Min-Heap) to repeatedly extract and merge the two lowest-frequency nodes in `O(n log n)` time.
Q4.5: In the Greedy 'Activity Selection Problem' (scheduling the maximum number of non-overlapping intervals in a single lecture hall), in what order must the activities be sorted?
(A) In ascending order of their Start times
(B) In ascending order of their Duration (`f_i − s_i`)
(C) In ascending order of their FINISH times ✅
(D) In descending order of Start times
Answer (C): In ascending order of their FINISH times (`f₁ ≤ f₂ ≤ ... ≤ f_n`) — Always picking the compatible activity that **finishes earliest** leaves the maximum remaining time for future activities (`O(n log n)`).

6 Questions in Booklet
📌 5.1 Dynamic Programming — 0/1 Knapsack, LCS, Matrix Chain Multiplication, Floyd-Warshall & Bellman-Ford
Key Formulas & Rules
  • 🔹 0/1 Knapsack = O(n·W) (Pseudo-polynomial)
  • 🔹 Longest Common Subsequence (LCS) = O(m·n)
  • 🔹 Matrix Chain Multiplication = O(n³) (Catalan C_(n-1) ways)
  • 🔹 Floyd-Warshall All-Pairs Shortest Path = Θ(V³)
Simple Exam Points
  • Dynamic Programming solves problems exhibiting Optimal Substructure AND Overlapping Subproblems by storing intermediate subproblem results via Top-Down Memoization (lookup table) or Bottom-Up Tabulation.
  • Core Recurrences: (1) 0/1 Knapsack: `dp[i][w] = max(dp[i-1][w], val[i] + dp[i-1][w - wt[i]])`
  • (2) LCS of strings X[1..m] and Y[1..n]: if `X[i] == Y[j]` then `1 + L[i-1, j-1]`, else `max(L[i-1, j], L[i, j-1])`
  • (3) Matrix Chain Multiplication of A_i (p_(i-1) × p_i): `m[i,j] = min_{i<=k<j} (m[i,k] + m[k+1,j] + p_(i-1)·p_k·p_j)`.
  • Scalar multiplications to multiply a (p × q) matrix with a (q × r) matrix is `p × q × r`.
✅ Direct Exam Example: Worked Matrix Chain Math: Multiply 3 matrices A1(10×100), A2(100×5), A3(5×50). Parenthesization 1: `((A1·A2)·A3)` costs `10×100×5 + 10×5×50 = 5,000 + 2,500 = 7,500` multiplications. Parenthesization 2: `(A1·(A2·A3))` costs `100×5×50 + 10×100×50 = 25,000 + 50,000 = 75,000` multiplications! Optimal cost = 7,500.
💡 Exam Shortcut / Trap: Hinglish Tip: Divide & Conquer me subproblems 'Independent (Disjoint)' hote hain, jabki Dynamic Programming me subproblems 'Overlapping' hote hain! Aur Floyd-Warshall O(V³) Dynamic Programming algorithm hai.

📝 Chapter 5 — Practice Questions & Simple Explanations

Q5.1: What are the two core hallmarks of a problem that can be solved by Dynamic Programming (DP)?
(A) 1. Random Guessing and 2. No Subproblems
(B) 1. Divide and Conquer without overlap
(C) 1. Optimal Substructure and 2. Overlapping Subproblems ✅
(D) 1. Exponential Memory only
Answer (C): 1. Optimal Substructure and 2. Overlapping Subproblems (solved via Memoization or Tabulation) — Divide & Conquer solves disjoint (independent) subproblems, whereas Dynamic Programming caches answers to **Overlapping Subproblems** in a table.
Q5.2: What is the time complexity of the Dynamic Programming solution for the 0/1 Knapsack problem with `n` items and knapsack capacity `W`?
(A) Θ(n log n)
(B) Θ(n²)
(C) Θ(W²)
(D) Θ(n × W) ✅
Answer (D): Θ(n × W) (Pseudo-polynomial time) — The 2D DP table `dp[0..n][0..W]` has `(n + 1)(W + 1)` cells, each filled in `O(1)` time via `max(dp[i-1][w], val[i] + dp[i-1][w - wt[i]])`.
Q5.3: In the Longest Common Subsequence (LCS) problem for two strings `X = 'ABCBDAB'` (length `m`) and `Y = 'BDCABA'` (length `n`), what is the DP time complexity?
(A) Θ(m × n) ✅
(B) Θ(m + n)
(C) Θ(2^m)
(D) Θ(m log n)
Answer (A): The 2D LCS table `L[0..m][0..n]` takes `Θ(m × n)` time (and can be optimized to `O(min(m, n))` space).
Q5.4: Which Dynamic Programming algorithm computes All-Pairs Shortest Paths (APSP) between every pair of vertices in a weighted graph in `Θ(V³)` time?
(A) Dijkstra's Algorithm
(B) Floyd-Warshall Algorithm (`D[i][j] = min`) ✅
(C) Prim's Algorithm
(D) Kruskal's Algorithm
Answer (B): Floyd-Warshall Algorithm (`D[i][j] = min(D[i][j], D[i][k] + D[k][j])`) — Floyd-Warshall uses 3 nested loops (`k, i, j` from `1` to `V`) in `Θ(V³)` time and `Θ(V²)` space (Warshall's algorithm computes Transitive Closure in `Θ(V³)`).
Q5.5: In Dynamic Programming, storing already computed subproblem results in a lookup table to avoid re-computation is called:
(A) Backtracking
(B) Hashing
(C) Memoization (Top-Down) or Tabulation (Bottom-Up) ✅
(D) Recursion only
Answer (C): Memoization caches recursive subproblem outputs so each overlapping subproblem is solved only once.

📌 6.1 Graph Algorithms — BFS, DFS, Topological Sort, Kruskal/Prim MST & Dijkstra vs Bellman-Ford
Key Formulas & Rules
  • 🔹 BFS / DFS (Adjacency List) = Θ(V + E), (Adjacency Matrix) = Θ(V²)
  • 🔹 Kruskal MST = O(E log E) or O(E log V)
  • 🔹 Prim MST (Binary Heap) = O((V + E) log V)
  • 🔹 Dijkstra = O((V + E) log V)
  • 🔹 Bellman-Ford = O(V · E)
Simple Exam Points
  • BFS uses a FIFO Queue (finds shortest path in unweighted graphs and level-order traversal)
  • DFS uses a LIFO Stack / Recursion (detects cycles via Back Edges, finds Articulation Points, Connected Components, and Topological Sort of a DAG).
  • Minimum Spanning Tree (MST — connects all V vertices with exactly V − 1 edges and minimum total weight): Kruskal's Algorithm sorts all edges and adds the lightest edge that doesn't form a cycle using Disjoint-Set Union-Find (best for sparse graphs)
  • Prim's Algorithm grows a single connected tree from a start vertex (best for dense graphs).
  • Shortest Path: Dijkstra's Greedy algorithm fails on negative edge weights (particularly negative cycles)
  • Bellman-Ford relaxes all E edges (V − 1) times (handles negative weights and detects negative-weight cycles on the V-th iteration).
✅ Direct Exam Example: Spanning Tree Count (Cayley's Formula): A complete undirected graph K_n on n labeled vertices has exactly n^(n−2) distinct spanning trees (e.g., for K_3 -> 3^1 = 3; for K_4 -> 4^2 = 16; for K_5 -> 5^3 = 125 spanning trees).
💡 Exam Shortcut / Trap: Exam Trap: Agar graph ke saare edge weights DISTINCT (alag-alag) hon, to us graph ka Minimum Spanning Tree (MST) hamesha 100% UNIQUE hota hai! Aur Dijkstra negative weight edges par fail ho sakta hai, jabki Bellman-Ford O(V·E) me sahi kaam karta hai.

📖 Chapter 7: NP-Completeness — Complexity Classes — P, NP, NP-Hard, NP-Complete, Polynomial Reductions & Cook-Levin Theorem

2 Questions in Booklet
📌 7.1 Complexity Classes — P, NP, NP-Hard, NP-Complete, Polynomial Reductions & Cook-Levin Theorem
Key Formulas & Rules
  • 🔹 Polynomial-Time Reduction A <=_p B: If A is NP-Hard and A <=_p B, then B is NP-Hard!
  • 🔹 NP-Complete = NP ∩ NP-Hard
  • 🔹 Cook-Levin Theorem (1971): 3-SAT / SAT is the FIRST NP-Complete problem
Simple Exam Points
  • Class P: Decision problems solvable in polynomial time O(n^k) by a Deterministic Turing Machine (e.g., Sorting, Shortest Path, MST, 2-SAT, Eulerian Circuit, Linear Programming).
  • Class NP (Nondeterministic Polynomial time): Decision problems solvable in polynomial time by a Nondeterministic Turing Machine, equivalently problems whose candidate solution (certificate) can be VERIFIED in deterministic polynomial time!
  • Note: P ⊆ NP is proven true.
  • A problem X is NP-Hard if every problem in NP reduces to X in polynomial time (Y <=_p X)
  • X does not have to be in NP itself (e.g., the Halting Problem is NP-Hard and Undecidable, so not in NP!).
  • X is NP-Complete if (1) X ∈ NP, AND (2) X is NP-Hard.
  • Classic NP-Complete Problems: 3-SAT, Clique, Vertex Cover, Independent Set, Hamiltonian Cycle, Travelling Salesman Decision Problem (TSP), Graph k-Coloring (k>=3), Subset Sum, 0/1 Knapsack.
✅ Direct Exam Example: Reduction Direction Trap: To prove a new problem B is NP-Hard using a known NP-Complete problem A (like 3-SAT), you must reduce A TO B (`3-SAT <=_p B`), NEVER B to 3-SAT!
💡 Exam Shortcut / Trap: Hinglish Tip: 'NP' ka full form 'Non-Polynomial' NAHI balki 'Nondeterministic Polynomial Time' hota hai! Aur Eulerian Circuit (visit every edge once) O(V+E) Class P me hai, jabki Hamiltonian Cycle (visit every vertex once) NP-Complete hai!

📝 Chapter 7 — Practice Questions & Simple Explanations

Q7.1: In Computational Complexity Theory, what is the relation among `P`, `NP`, `NP-Hard`, and `NP-Complete` problems?
(A) NP-Complete problems cannot be verified in polynomial time
(B) Sorting and Binary Search are NP-Complete
(C) Halting Problem is in P
(D) P ⊆ NP; a problem is NP-Complete if it is BOTH in NP AND NP-Hard ✅
Answer (D): P ⊆ NP; a problem is NP-Complete if it is BOTH in NP (verifiable in polynomial time) AND NP-Hard (every problem in NP reduces to it in polynomial time) — Classic NP-Complete problems: 3-SAT (Cook-Levin Theorem), Traveling Salesperson Decision (TSP), 0/1 Knapsack, Hamiltonian Cycle, Vertex Cover, Graph Coloring. The Halting Problem is Undecidable (NP-Hard, not in NP).

(C) Problem A is Undecidable
(D) Problem B is exponential
Answer (A): Problem A is also in P (solvable in polynomial time) — Polynomial-time reducibility transfers polynomial solvability backward from B to A.
