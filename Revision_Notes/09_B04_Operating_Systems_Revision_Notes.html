📖 Chapter 1: Process & Scheduling — Process States (5/7-State Model), PCB, System Calls (fork/exec) & CPU Scheduling Algorithms

29 Questions in Booklet
📌 1.1 Process States (5/7-State Model), PCB, System Calls (fork/exec) & CPU Scheduling Algorithms
Key Formulas & Rules
  • 🔹 Turnaround Time (TAT) = Completion Time (CT) − Arrival Time (AT)
  • 🔹 Waiting Time (WT) = TAT − Burst Time (BT)
  • 🔹 n consecutive fork() calls create 2^n total processes (2^n − 1 child processes)
Simple Exam Points
  • Process Control Block (PCB) stores PID, Process State, Program Counter, CPU Registers, Memory page-table pointers, and Open File Descriptors.
  • Context Switching saves the current process's PCB and loads the next process's PCB (pure overhead — zero useful work done).
  • Note: User-level threads share Code, Data, Heap, and Open Files, but each thread has its OWN private Stack, Program Counter, and Register set!
  • CPU Scheduling Comparison: (1) FCFS: Non-preemptive, suffers from Convoy Effect
  • (2) SJF / SRTF (Preemptive SJF): Provably optimal for minimum average waiting time, but suffers from Starvation (solved by Aging)
  • (3) Round Robin (RR): Preemptive time-quantum q (if q -> ∞, RR degenerates to FCFS
  • if q -> 0, excessive context-switch overhead), ideal for Time-Sharing systems
  • (4) Highest Response Ratio Next (HRRN): Response Ratio = (W + S) / S (prevents starvation via waiting time W).
✅ Direct Exam Example: Worked Scheduling Numerical: Three processes P1(AT=0, BT=8), P2(AT=1, BT=4), P3(AT=2, BT=2) run under Preemptive SRTF. Gantt: [0-1: P1(rem 7)], [1-2: P2(rem 3)], [2-4: P3(completes at 4)], [4-7: P2(completes at 7)], [7-14: P1(completes at 14)]. TATs: P1=14-0=14, P2=7-1=6, P3=4-2=2 -> Avg TAT = 22/3 = 7.33 ms; WTs: P1=6, P2=2, P3=0 -> Avg WT = 8/3 = 2.67 ms.
💡 Exam Shortcut / Trap: Hinglish Tip: n baar `fork()` call karne par total processes = 2^n bante hain aur naye child processes = 2^n − 1 bante hain! Threads apas me Code, Data aur Files share karte hain, par STACK aur REGISTER har thread ka apna alag hota hai!

📖 Chapter 2: Synchronization & Semaphores — Process Synchronization, Critical Section Criteria, Peterson's Solution & Semaphores

10 Questions in Booklet
📌 2.1 Process Synchronization, Critical Section Criteria, Peterson's Solution & Semaphores
Key Formulas & Rules
  • 🔹 3 Critical Section Requirements: Mutual Exclusion (Mandatory) + Progress (Mandatory) + Bounded Waiting
  • 🔹 Semaphore wait(S)/P(S): while(S<=0); S--;
  • 🔹 signal(S)/V(S): S++;
Simple Exam Points
  • A Race Condition occurs when multiple concurrent processes access and manipulate shared data and the outcome depends on the exact order of execution.
  • Any valid Critical Section solution must guarantee: (1) Mutual Exclusion (at most 1 process inside CS at a time), (2) Progress (processes outside CS cannot block others from entering), and (3) Bounded Waiting (upper bound on how many times other processes can enter before a waiting process gets its turn).
  • Dijkstra's Semaphore supports two atomic operations: P(S) / wait(S) / down(S) and V(S) / signal(S) / up(S).
  • For a Counting Semaphore initialized to S_0: after m wait(P) operations and n signal(V) operations, final value is S = S_0 − m + n.
  • If S < 0, then |S| is the exact number of processes currently blocked in the semaphore queue!
✅ Direct Exam Example: Worked Semaphore Math: A counting semaphore is initialized to S = 12. Subsequently, 20 P (wait) operations and 15 V (signal) operations are executed. Final value S = 12 − 20 + 15 = 7. If instead S_0 = 3, 10 P ops and 4 V ops occur -> S = 3 − 10 + 4 = −3 (meaning 3 processes are blocked in queue).
💡 Exam Shortcut / Trap: Exam Trap: Counting Semaphore me agar S ki value negative (jaise −4) hai, to iska matlab hai ki is waqt 4 processes semaphore ki waiting queue me BLOCKED (sleep state me) hain!

Q2.1: Which real-time scheduling algorithm assigns highest static priority to the periodic task with the shortest period (`Priority ∝ 1 / Period`)?
(A) Earliest Deadline First (EDF — Dynamic priority)
(B) Rate-Monotonic Scheduling (RMS) ✅
(C) FCFS
(D) Lottery Scheduling
Answer (B): RMS uses static priorities (`shorter period = higher priority`); EDF uses dynamic priorities (`closer deadline = higher priority`).
Q2.2: When two or more concurrent processes read and write shared data without synchronization and the final outcome depends on the exact order of execution, it is called a:
(A) Deadlock
(B) Belady's Anomaly
(C) Race Condition ✅
(D) Fragmentation
Answer (C): A Race Condition is prevented by enforcing Mutual Exclusion in the Critical Section.
Q2.3: In Edsger Dijkstra's Semaphore operations, what do the atomic operations `P(S)` (or `wait(S)`) and `V(S)` (or `signal(S)`) do?
(A) wait(S) increments S and signal(S) decrements S
(B) Both set S = 0
(C) wait(S) deletes the semaphore
(D) wait(S) decrements S; signal(S) increments S ✅
Answer (D): wait(S) decrements S (`S = S − 1`, blocking if S < 0); signal(S) increments S (`S = S + 1`, waking a blocked process) — `P(S)` (Proberen / Wait) acquires a resource (`S--`); `V(S)` (Verhogen / Signal) releases a resource (`S++`).
Q2.4: A Counting Semaphore is initialized to `S = 10`. After `6 wait(S)` operations and `4 signal(S)` operations are executed, what is the current value of `S`?
(A) 8 (10 − 6 + 4 = 8) ✅
(B) 12
(C) 2
(D) 0
Answer (A): Current value `S = Initial − Waits + Signals = 10 − 6 + 4 = 8`.
Q2.5: A Counting Semaphore is initialized to `S = 1` (acting as a Mutex). If 5 processes simultaneously attempt to enter the critical section by calling `wait(S)`, what will the value of `S` become and how many processes will be blocked?
(A) S = 0 and 0 processes blocked
(B) S = −4 (1 − 5 = −4), and 4 processes are blocked in the semaphore queue ✅
(C) S = −5 and 5 processes blocked
(D) S = +4
Answer (B): 1 process enters the CS (`S: 1 -> 0`), and the other 4 processes block (`S: 0 -> −4`). When `S < 0`, `|S|` equals the exact number of blocked processes!

📖 Chapter 3: Deadlocks & Banker's — Deadlocks — Four Coffman Conditions, Resource Allocation Graph & Banker's Algorithm

10 Questions in Booklet
📌 3.1 Deadlocks — Four Coffman Conditions, Resource Allocation Graph & Banker's Algorithm
Key Formulas & Rules
  • 🔹 Need Matrix: Need[i][j] = Max[i][j] − Allocation[i][j]
  • 🔹 Minimum Resources to Guarantee Deadlock-Free Execution for n processes needing k_i each: R >= Σ(k_i − 1) + 1
Simple Exam Points
  • Deadlock occurs ONLY if all four Coffman conditions hold simultaneously: (1) Mutual Exclusion (non-sharable resource), (2) Hold and Wait, (3) No Preemption, and (4) Circular Wait.
  • In a Resource Allocation Graph (RAG): If each resource type has only a SINGLE instance, a cycle is both a NECESSARY and SUFFICIENT condition for deadlock
  • if resource types have MULTIPLE instances, a cycle is a NECESSARY but NOT SUFFICIENT condition!
  • Deadlock Prevention invalidates one of the 4 conditions (e.g., imposing a global numerical ordering on resource types prevents Circular Wait, which is the most practical prevention technique).
  • Deadlock Avoidance uses Dijkstra's Banker's Algorithm (O(m · n²) safety algorithm checking if a Safe Sequence exists).
  • Note: Every Deadlock state is an Unsafe state, but NOT every Unsafe state leads to a Deadlock!
✅ Direct Exam Example: Worked Deadlock Formula: A system has 4 processes, each requiring at most 3 units of magnetic tape drives. What is the minimum number of tape drives so that the system never deadlocks? R_min = 4 × (3 − 1) + 1 = 8 + 1 = 9 tape drives.
💡 Exam Shortcut / Trap: Hinglish Tip: Deadlock-free formula (Exam Superhero Formula!): Agar n processes hain aur har process ko maximum k instances chahiye, to Deadlock hone ki maximum resources = n(k − 1), aur 100% Deadlock-Free hone ke liye minimum resources R = n(k − 1) + 1 chahiye!

📝 Chapter 3 — Practice Questions & Simple Explanations

Q3.1: What are the FOUR necessary and sufficient Coffman Conditions that must hold simultaneously for a Deadlock to occur?
(A) 1. Paging, 2. Thrashing, 3. Compaction, and 4. Swapping
(B) 1. Progress, 2. Bounded Waiting, 3. Starvation, and 4. Aging
(C) 1. Atomicity, 2. Consistency, 3. Isolation, and 4. Durability
(D) 1. Mutual Exclusion, 2. Hold and Wait, 3. No Preemption, and 4. Circular Wait ✅
Answer (D): Deadlock Prevention breaks at least ONE of the 4 Coffman conditions.
Q3.2: Which of the 4 Coffman Deadlock conditions is broken when the OS imposes a strict global numerical ordering on all resource types and requires every process to request resources in increasing order?
(A) Circular Wait ✅
(B) Mutual Exclusion
(C) No Preemption
(D) Hold and Wait
Answer (A): Circular Wait (the most practical Deadlock Prevention method) — Strict ascending resource numbering mathematically prevents a cycle from ever forming, eliminating Circular Wait.
Q3.3: In a Resource Allocation Graph (RAG), if a cycle exists, when does a cycle guarantee a Deadlock vs when is it only a necessary (not sufficient) condition?
(A) A cycle always means deadlock even with 100 instances
(B) If every resource type has ONLY 1 instance, a cycle is BOTH necessary and sufficient for Deadlock ✅
(C) A cycle never means deadlock
(D) Only acyclic graphs have deadlocks
Answer (B): If every resource type has ONLY 1 instance, a cycle is BOTH necessary and sufficient for Deadlock; if resources have multiple instances, a cycle is necessary but NOT sufficient. Single-instance RAG: `Cycle <=> Deadlock`. Multi-instance RAG: requires Banker's Safety Algorithm.
Q3.4: In Dijkstra's Banker's Algorithm for Deadlock Avoidance, how is the `Need` matrix calculated from the `Max` and `Allocation` matrices?
(A) Need = Max + Allocation
(B) Need = Available − Allocation
(C) Need[i][j] = Max[i][j] − Allocation[i][j] ✅
(D) Need = Max / Allocation
Answer (C): A process `P_i` can finish in the Safety Algorithm if `Need[i] ≤ Work (Available)`.
Q3.5: In Banker's Algorithm, what is the relation between a 'Safe State', an 'Unsafe State', and a 'Deadlock State'?
(A) Every Unsafe State is immediately an active Deadlock
(B) A Safe State can have a Deadlock
(C) Safe and Unsafe states are identical
(D) Every Safe State is guaranteed to be deadlock-free ✅
Answer (D): Every Safe State is guaranteed to be deadlock-free; an Unsafe State is NOT necessarily a deadlock, but MAY lead to a deadlock if processes request their maximum claim. `Deadlock ⊂ Unsafe States`; Safe states have at least one valid Safe Sequence `<P₁, P₂, ..., P_n>`.

📖 Chapter 4: Memory & Paging — Memory Management — Contiguous Allocation, Paging, TLB & Multi-Level Page Tables

6 Questions in Booklet
📌 4.1 Memory Management — Contiguous Allocation, Paging, TLB & Multi-Level Page Tables
Key Formulas & Rules
  • 🔹 EMAT with TLB = α(t_tlb + t_mem) + (1 − α)(t_tlb + 2·t_mem) [for 1-level PT]
  • 🔹 Logical Address (m bits) = Page Number p (m − d bits) + Page Offset d (d bits, Page Size = 2^d)
Simple Exam Points
  • Contiguous Allocation Strategies (First Fit, Best Fit, Worst Fit): First Fit is generally fastest
  • Best Fit leaves tiny unusable holes
  • all variable-partition schemes suffer from External Fragmentation (compaction resolves it).
  • Paging divides Physical Memory into fixed-size Frames and Logical Memory into equal-size Pages (eliminating External Fragmentation completely, though the last page of a process suffers average Internal Fragmentation of 0.5 × Page Size!).
  • Segmentation divides memory by logical user units (code, stack, symbol table) using `<segment-number, offset>` validated against a `[Base, Limit]` register pair (suffers from External Fragmentation, zero Internal Fragmentation).
✅ Direct Exam Example: Worked TLB EMAT Math: TLB hit ratio α = 90% (0.9), TLB access time = 10 ns, Main Memory access time = 100 ns (1-level page table). EMAT = 0.9 × (10 + 100) + 0.1 × (10 + 200) = 99 + 21 = 120 ns.
💡 Exam Shortcut / Trap: Exam Trap: Paging me EXTERNAL Fragmentation ZERO hoti hai (sirf Internal Fragmentation hoti hai), jabki Segmentation me INTERNAL Fragmentation ZERO hoti hai (sirf External Fragmentation hoti hai)!

📝 Chapter 4 — Practice Questions & Simple Explanations

Q4.1: In Contiguous Memory Allocation (First-Fit, Best-Fit, Worst-Fit), what is the difference between 'Internal Fragmentation' and 'External Fragmentation'?
(A) External Fragmentation occurs inside a fixed page
(B) Internal Fragmentation is wasted space INSIDE an allocated fixed partition/page ✅
(C) Paging suffers from External Fragmentation
(D) Segmentation suffers only from Internal Fragmentation
Answer (B): Internal Fragmentation is wasted space INSIDE an allocated fixed partition/page; External Fragmentation is when total free memory is sufficient for a request, but is scattered in non-contiguous small holes. Paging has NO External Fragmentation (only slight Internal Fragmentation in the last page); Segmentation has External Fragmentation (solved by Compaction or Paged Segmentation).
Q4.2: Among First-Fit, Best-Fit, and Worst-Fit dynamic partition allocation strategies, which one is generally the FASTEST, and which one leaves behind the tiniest unusable leftover slivers?
(A) Worst-Fit leaves the smallest holes
(B) Best-Fit is faster than First-Fit
(C) First-Fit is the fastest ✅
(D) All three leave identical holes
Answer (C): First-Fit is the fastest; Best-Fit leaves behind the smallest unusable leftover holes. First-Fit scans only until the first big-enough hole is found; Best-Fit scans the whole list (unless sorted) and leaves tiny fragments.
Q4.3: In a Paging system with a 32-bit Logical (Virtual) Address and a Page Size of `4 KB` (`2¹²` Bytes), how many bits are used for the Page Offset `d`, and how many Virtual Pages exist?
(A) Page Offset = 10 bits; VPN = 22 bits
(B) Page Offset = 16 bits; VPN = 16 bits
(C) Page Offset = 4 bits; VPN = 28 bits
(D) Page Offset = 12 bits; Virtual Page Number (VPN) = 32 − 12 = 20 bits ✅
Answer (D): Page Offset = 12 bits; Virtual Page Number (VPN) = 32 − 12 = 20 bits (`2²⁰ ≈ 1 Million` pages) — Since Page Size = Frame Size = `4 KB = 2¹² B`, the lower `12` bits are the Offset `d` (copied unchanged during translation), and the upper `20` bits are the Page Number `p`.
Q4.4: Why do modern 64-bit architectures (like x86-64 and ARM64) use 'Hierarchical (Multi-Level) Page Tables' or 'Inverted Page Tables' instead of a single flat Page Table?
(A) Because a flat single-level page table for a 48-bit/64-bit virtual address space would require Terabytes of contiguous RAM per process! ✅
(B) To increase the page fault rate
(C) Because TLB does not work with 1-level page tables
(D) To eliminate the CPU cache
Answer (A): Multi-level page tables allocate inner page-table pages lazily only for virtual memory regions actually used by the process; an Inverted Page Table has only 1 global entry per Physical Frame.
Q4.5: What is the purpose of 'Compaction' (Memory Defragmentation) in dynamic contiguous memory allocation?
(A) Solving Internal Fragmentation inside pages
(B) Shuffling allocated memory blocks together to consolidate scattered small free holes into one large contiguous free block ✅
(C) Erasing the hard disk
(D) Increasing CPU clock speed
Answer (B): Shuffling allocated memory blocks together to consolidate scattered small free holes into one large contiguous free block (solving External Fragmentation) — Compaction solves External Fragmentation and requires dynamic runtime relocation (Base/Limit registers).

📖 Chapter 5: Virtual Memory & Belady's — Virtual Memory, Demand Paging, Page Replacement (FIFO, Optimal, LRU) & Thrashing

8 Questions in Booklet
📌 5.1 Virtual Memory, Demand Paging, Page Replacement (FIFO, Optimal, LRU) & Thrashing
Key Formulas & Rules
  • 🔹 EMAT with Page Fault rate p: EMAT = (1 − p) × t_mem + p × t_page_fault
  • 🔹 Belady's Anomaly occurs ONLY in FIFO (Never in Stack Algorithms: LRU, Optimal)
Simple Exam Points
  • Demand Paging loads pages into RAM only when referenced
  • accessing a page with Valid-Invalid bit = 'i' triggers a Page Fault trap to the OS.
  • Page Replacement Algorithms: (1) FIFO: Replaces oldest loaded page
  • suffers from Belady's Anomaly (increasing allocated page frames can INCREASE page faults, e.g., reference string 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5 gives 9 faults with 3 frames vs 10 faults with 4 frames!)
  • (2) Optimal (OPT / Belady's MIN): Replaces page that will not be used for the longest period in the future (lowest possible fault rate, used as theoretical benchmark)
  • (3) LRU (Least Recently Used): Replaces page unused for longest past time
  • belongs to Stack Algorithms (guaranteed free of Belady's Anomaly).
  • Thrashing occurs when degree of multiprogramming is too high and processes lack their Working Set of frames, spending more time paging than executing (CPU utilization plummets).
✅ Direct Exam Example: Worked Page Fault EMAT: Memory access time = 100 ns, Page fault service time = 10 ms (10^7 ns), Page fault rate p = 1 in 10,000 (10^-4). EMAT = (1 − 0.0001)×100 + 0.0001 × 10^7 = 100 + 1000 = 1100 ns (an 11x slowdown from just a 0.01% fault rate!).
💡 Exam Shortcut / Trap: Hinglish Tip: Page Fault Service Time (~8 milliseconds = 8,000,000 ns) RAM access (100 ns) se ~80,000 guna bada hota hai! Aur LRU aur Optimal 'Stack Algorithms' hain isliye unme kabhi Belady's Anomaly nahi aati.

📝 Chapter 5 — Practice Questions & Simple Explanations

Q5.1: For the page reference string `7, 0, 1, 2, 0, 3, 0, 4` (length 8) with `3` initially empty page frames, how many Page Faults and Page Hits occur under FIFO page replacement?
(A) 6 Page Faults and 2 Page Hits
(B) 8 Page Faults and 0 Page Hits
(C) 5 Page Faults and 3 Page Hits
(D) 7 Page Faults and 1 Page Hit ✅
Answer (D): Steps: 7(F), 0(F), 1(F) -> [7,0,1]; 2(F replaces 7) -> [2,0,1]; 0(HIT!); 3(F replaces 0) -> [2,3,1]; 0(F replaces 1) -> [2,3,0]; 4(F replaces 2) -> [4,3,0]. Total = 7 Faults, 1 Hit.
Q5.2: Which hardware bit in a Page Table Entry (PTE) indicates whether the virtual page is currently resident in physical RAM (`1`) or on disk swap space (`0`), and which bit indicates whether the page has been modified (`1`)?
(A) Valid/Invalid (Present) Bit indicates RAM residency ✅
(B) Dirty Bit indicates RAM residency
(C) Reference Bit deletes the page
(D) Protection Bit measures page size
Answer (A): Valid/Invalid (Present) Bit indicates RAM residency; Dirty (Modified) Bit indicates the page was written to and must be saved to disk on eviction. Accessing a page with `Valid/Present = 0` triggers a **Page Fault Trap** to the OS.
Q5.3: Which Page Replacement Algorithm suffers from 'Belady's Anomaly' (where increasing the number of physical RAM frames can paradoxically INCREASE the number of page faults)?
(A) Optimal (OPT / Belady's MIN) Algorithm
(B) FIFO (First-In, First-Out) Page Replacement ✅
(C) LRU (Least Recently Used) Algorithm
(D) LFU Stack Algorithm
Answer (B): FIFO is not a stack algorithm and exhibits Belady's Anomaly (e.g., on reference string `1,2,3,4,1,2,5,1,2,3,4,5`, 3 frames -> 9 faults, 4 frames -> 10 faults!). Optimal and LRU are stack algorithms and NEVER suffer from Belady's Anomaly.
Q5.4: Which Page Replacement Algorithm gives the lowest possible page fault rate of all algorithms, and why can it not be implemented directly in a real live OS?
(A) LRU; because it is too slow
(B) FIFO; because it needs a queue
(C) Optimal (OPT) Page Replacement; requires future knowledge of the reference string ✅
(D) Second-Chance Clock; because it needs a reference bit
Answer (C): Optimal (OPT) Page Replacement (replaces the page that will not be used for the longest period of time in the FUTURE); requires future knowledge of the reference string — Optimal (OPT) is used as a theoretical benchmark to compare practical algorithms like LRU and Clock (Second-Chance).
Q5.5: For the page reference string `7, 0, 1, 2, 0, 3, 0, 4` with `3` initially empty page frames, how many Page Faults occur under FIFO page replacement?
(A) 8 Page Faults
(B) 4 Page Faults
(C) 5 Page Faults
(D) 6 Page Faults ✅
Answer (D): 7(F), 0(F), 1(F) [7,0,1]; 2(F replaces 7) [2,0,1]; 0(Hit); 3(F replaces 0) [2,3,1]; 0(F replaces 1) [2,3,0]; 4(F replaces 2) [4,3,0]? Wait: let's count: 7, 0, 1, 2, 3, 0, 4 = 7 faults (only the first 0 at step 5 is a Hit => 8 − 1 = 7 Page Faults!).

📖 Chapter 6: Disk Scheduling & Files — Disk Scheduling Algorithms (FCFS, SSTF, SCAN, C-SCAN, LOOK, C-LOOK) & File Allocation

2 Questions in Booklet
📌 6.1 Disk Scheduling Algorithms (FCFS, SSTF, SCAN, C-SCAN, LOOK, C-LOOK) & File Allocation
Key Formulas & Rules
  • 🔹 Disk Access Time = Seek Time (Moving arm to cylinder — LARGEST component!) + Rotational Latency (0.5 × 60/RPM) + Transfer Time
Simple Exam Points
  • Disk Arm Scheduling: (1) FCFS: Fair but high head movement
  • (2) SSTF (Shortest Seek Time First): Greedy choice of nearest cylinder to current head position — minimizes seek time but causes starvation of distant tracks
  • (3) SCAN (Elevator Algorithm): Moves toward one end servicing requests all the way to the boundary (0 or MaxCylinder-1), then reverses direction
  • (4) C-SCAN (Circular SCAN): Services in one direction only, jumps back to start boundary without servicing on return sweep (uniform wait time)
  • (5) LOOK & C-LOOK: Reverse direction at the LAST REQUEST in that direction rather than hitting the physical disk end boundary!
  • File Allocation: Contiguous (fast random access, external fragmentation), Linked/FAT (no external fragmentation, slow sequential-only traversal unless FAT cached), Indexed / UNIX Inode (12 direct pointers + single/double/triple indirect blocks).
✅ Direct Exam Example: Worked SSTF Trace: Head starts at cylinder 50; queue = [82, 170, 43, 140, 24, 16, 190]. Nearest to 50 is 43 (7) -> 24 (19) -> 16 (8) -> 82 (66) -> 140 (58) -> 170 (30) -> 190 (20). Total head movement = (50 − 16) + (190 − 16) = 34 + 174 = 208 cylinders.
💡 Exam Shortcut / Trap: Exam Trap: SCAN aur C-SCAN disk ke akhiri physical boundary cylinder (0 ya 199) ko chhoo kar aate hain, jabki LOOK aur C-LOOK akhiri request par hi mud jate hain! Aur Disk Access Time me sabse bada hissa 'Seek Time' hota hai.

Q6.1: A disk head is currently at cylinder `50` (moving towards higher cylinders on a `0–199` disk) and the request queue is `82, 170, 43, 140, 24, 16, 190`. What is the total head movement under SCAN (Elevator) vs LOOK?
(A) SCAN = 314 and LOOK = 332
(B) Both are 200 cylinders
(C) SCAN = 149 cylinders
(D) SCAN: (199 − 50) + (199 − 16) = 149 + 183 = 332 cylinders ✅
Answer (D): SCAN: (199 − 50) + (199 − 16) = 149 + 183 = 332 cylinders; LOOK: (190 − 50) + (190 − 16) = 140 + 174 = 314 cylinders. SCAN (goes to end 199 then down to 16): (199 − 50) + (199 − 16) = 149 + 183 = 332 cylinders; LOOK (reverses at 190 then down to 16): (190 − 50) + (190 − 16) = 140 + 174 = 314 cylinders — SCAN travels all the way to the physical disk boundary (`199` or `0`), whereas LOOK reverses direction immediately at the last extreme request (`190`).
Q6.2: Among disk space allocation methods — (1) Contiguous Allocation, (2) Linked Allocation (FAT), and (3) Indexed Allocation (Inodes) — which one supports direct O(1) random block access WITHOUT suffering from external fragmentation?
(A) Indexed Allocation (used in Unix/Linux Inodes) ✅
(B) Contiguous Allocation (suffers from External Fragmentation)
(C) Simple Linked Allocation (slow O(n) sequential pointer chasing)
(D) None of these
Answer (A): Indexed allocation groups all block pointers of a file into an Index Block (Inode), supporting fast random access without external fragmentation.

📖 Chapter 7: Linux Commands & Kernels — Linux Kernel Architecture, Inodes, Octal Permissions (chmod/umask) & Essential CLI Commands

📌 7.1 Linux Kernel Architecture, Inodes, Octal Permissions (chmod/umask) & Essential CLI Commands
Key Formulas & Rules
  • 🔹 Octal Permissions: r = 4, w = 2, x = 1
  • 🔹 chmod 755 = rwxr-xr-x
  • 🔹 Default File Creation = 666 − umask
  • 🔹 Default Directory Creation = 777 − umask
Simple Exam Points
  • In UNIX/Linux, everything is represented as a file described by an Inode (Index Node).
  • An Inode stores File Mode/Permissions, Owner UID/GID, File Size, Timestamps (atime, mtime, ctime), Link Count, and Data Block pointers — the Inode NEVER stores the Filename (the filename-to-inode mapping is stored inside the parent Directory entry!).
  • Essential Linux Commands: `chmod` (change permissions), `chown` (change owner), `grep` (search regex pattern inside files), `find` (search files in directory hierarchy), `ps` / `top` (view active processes), `kill -9 <PID>` (send SIGKILL=9, uncatchable termination), `ln` (hard link — shares same inode number) vs `ln -s` (symbolic/soft link — creates new inode pointing to path), `df` (filesystem disk space) vs `du` (directory space usage).
✅ Direct Exam Example: Worked Permission Check: What symbolic string corresponds to `chmod 750 script.sh`? Owner = 7 (4+2+1 = rwx), Group = 5 (4+0+1 = r-x), Others = 0 (---) => `-rwxr-x---`.
💡 Exam Shortcut / Trap: Hinglish Tip: UNIX Inode ke andar File ka NAAM (Filename) kabhi store nahi hota — Filename Directory table me Inode number ke sath map hota hai! Aur `umask 022` hone par nayi file `666 − 022 = 644 (rw-r--r--)` aur naya folder `777 − 022 = 755 (rwxr-xr-x)` banta hai!

Q7.1: In a Unix/Linux File System (ext4), which data structure stores all file metadata (owner UID, permissions, size, timestamps, and direct/indirect disk block pointers) EXCEPT the human-readable filename?
(A) Superblock
(B) Inode ✅
(C) Boot Block
(D) FAT Table
Answer (B): Inode (Index Node — while the filename-to-Inode-number mapping is stored in the Directory entry!) — Exam Favorite: The **Filename is NOT stored inside the Inode**; the Directory file maps `(Filename -> Inode_Number)` (which is why multiple Hard Links can share the exact same Inode!).
Q7.2: In Linux file permissions, what does the command `chmod 754 script.sh` set for `(Owner/User, Group, Others)`?
(A) User = r--, Group = r-x, Others = rwx
(B) User = rw-, Group = r--, Others = ---
(C) User = rwx (7 = 4+2+1), Group = r-x (5 = 4+0+1), Others = r-- (4 = 4+0+0) -> `-rwxr-xr--` ✅
(D) All users get full rwx permissions
Answer (C): Octal weights: Read `r = 4`, Write `w = 2`, Execute `x = 1`. Thus `7 = rwx`, `6 = rw-`, `5 = r-x`, `4 = r--`, `0 = ---`.
Q7.3: In Linux, which command searches for lines matching a Regular Expression pattern inside files, and which command searches the directory hierarchy for files by name, size, or modification time?
(A) `ls` searches inside files and `cat` renames files
(B) `chmod` searches text and `chown` deletes files
(C) `pwd` searches patterns
(D) `grep` searches text patterns inside files ✅
Answer (D): `grep` searches text patterns inside files; `find` locates files in the directory hierarchy. `grep` (Global Regular Expression Print) filters file lines by regex; `find /path -name '*.c'` searches directories for matching files.
Q7.4: In Linux, what is the difference between a 'Hard Link' (`ln file hlink`) and a 'Soft / Symbolic Link' (`ln -s file slink`)?
(A) A Hard Link shares the exact same Inode number as the original file ✅
(B) A Soft Link shares the same Inode number as the original file
(C) A Hard Link breaks immediately when the original file is deleted
(D) A Hard Link can link directories across different partitions
Answer (A): A Hard Link shares the exact same Inode number as the original file; a Soft Link has a NEW Inode storing the pathname string. A Hard Link shares the exact same Inode number as the original file (cannot cross file systems, data survives if original filename is deleted); a Soft Link has a NEW Inode storing the pathname string (becomes a broken dangling link if original is deleted) — Deleting the original file breaks a Soft/Symbolic Link (`dangling pointer`), whereas a Hard Link keeps the file data alive until the Inode link count drops to 0.
Q7.5: In Linux, what do the commands `pwd`, `ls -la`, `ps aux`, `kill -9 <PID>`, and `top` do?

(B) `pwd` = print working directory ✅
(C) `kill -9` deletes a file from disk
(D) `ls` compiles C programs
Answer (B): `pwd` = print working directory; `ls -la` = list all files including hidden dot-files; `ps/top` = view running processes; `kill -9` = send SIGKILL to terminate a process. Note: `passwd` changes a user's password, whereas `pwd` prints the current working directory!
